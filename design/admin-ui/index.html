Design decisions

Separate admin plane

  • Own Cowboy listener on 127.0.0.1:8090 (app env janus_admin: port / bind) — never on the data-plane listener.
  • Caddy terminates TLS and may add IP allowlist or basic auth in front of /admin; the app still enforces its own session auth (defense in depth).

Auth model

  • Single operator password from JANUS_ADMIN_PASSWORD (fail closed: unset → no logins possible, listener still serves the login page).
  • Session cookie janus_admin_session: random 256-bit token, HttpOnly, SameSite=Strict, 12 h expiry, optional Secure flag.
  • 5 failed logins per source IP → 15 min lockout.
  • Every mutating form carries a per-session CSRF token; POSTs without a match are rejected with 403.
  • Logins, login failures and every mutation are written to the audit log.

Secret handling

  • Provider keys: pasted once → AES-256-GCM envelope via janus_secrets → plaintext discarded. The UI can only ever show key_id + weight + state.
  • Agent keys: generated server-side (sk- + random), stored as peppered HMAC hash. The full key is shown exactly once, in the response to the create POST — never re-displayed, never logged.
  • Model grants are explicit checkboxes; a key with no grants can call nothing.

Catalog mutations

  • All forms POST to the page URL with an action field; handlers validate, write via janus_db_conn, bump the config generation (CAS), and the reload propagates to the serving catalog.
  • PRG everywhere (303 redirects) with a flash message — except key creation, which renders the one-time reveal page directly.

Rendering

  • Server-rendered Erlang (Cowboy handlers + one layout module), this stylesheet served from priv/www. No client framework, no build step, no JS except native forms.
  • All dynamic output HTML-escaped; identifiers rendered in monospace.
