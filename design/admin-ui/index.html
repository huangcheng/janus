Route tree (TanStack Router)

/admin — layout route: sidebar chrome + auth guard (beforeLoad → /admin/login)
  ├─ index — dashboard · loader: GET /overview
  ├─ /providers — loader: GET /providers · modals for create/add-key/delete
  ├─ /models — loader: GET /models + GET /providers · modals for create/route/delete
  ├─ /keys — loader: GET /keys + GET /models · create modal w/ reveal-once state
  └─ /audit — loaders + ?action=&actor=&page= search params
/admin/login — outside the guard, own minimal layout

Interaction model

  • All mutations are modals — add provider, add key, add model, add route, create agent key; destructive actions (delete/revoke) get a danger-confirm modal with consequences spelled out.
  • Toggles act immediately (enable/disable is reversible) with an undo toast — no modal.
  • Key creation renders its one-time reveal inside the success state of the modal; closing it discards the plaintext forever.
  • Optimistic none — mutations await the API response, then invalidate the route loader (TanStack Query or loader revalidation).

Auth & security posture

  • Separate admin listener on 127.0.0.1:8090; Caddy fronts it with TLS (+ optional IP allowlist) while the app still enforces its own session auth.
  • Password from JANUS_ADMIN_PASSWORD; unset ⇒ fail closed (no login possible). 5 failed logins lock the IP 15 min.
  • Session cookie HttpOnly · SameSite=Strict · 12 h; CSRF token via X-Janus-CSRF on every mutation.
  • Provider secrets are write-only (AES-256-GCM at rest); agent keys stored as peppered HMAC hashes, revealed once.
  • Every mutation and login attempt lands in the audit log.

Visual language

  • OLED-dark canvas with a fixed radial mesh glow; glass sidebar with backdrop blur (the only blurred element).
  • Double-bezel cards: 2px shell + inner surface with top highlight; hairline white/8% borders, no gray lines.
  • Pill buttons with trailing circular icon, press-scale physics; motion on cubic-bezier(0.32, 0.72, 0, 1).
  • Geist / Plus Jakarta Sans for UI, Geist Mono / Cascadia for identifiers and code.
  • Status pills: green = enabled, amber = cooldown/warning, dim = off, red = destructive.
