# Entitlement Matrix + In-Request Failover — Audit

**1. Verdict:** GO WITH FIXES — the design is sound and the fail-open bias is correct, but the retry/cooldown/generation rules contradict each other in at least five places and the attempt budget is mis-counted.

**2. Critical risks**
- Probe cost: 786-call day-one bootstrap is fine against a 5000/day budget, but `JANUS_PROBE_DAILY_CALLS` is per-provider while advisory-lock single-flight is per-provider — no cross-replica counter shown besides `probe_budget_counters`; verify it is the actual gate, not aspirational.
- Deny-regex vs input-shape: anchored patterns are good, but A.2's default writes `error_code='input_shape'` for *unclassified* 400s, colliding with C.1's "KNOWN input-shape" definition.
- Latency: ceiling math (300−60−30−30=180s) is sound; first call unbounded is acceptable.
- Retry storm: no per-key in-flight cap; only per-key cooldown. Concurrent bursts on a healthy key are undamped.
- Streaming boundary is correctly drawn (commit = first byte to reply/stream).
- Balance starvation: closed by probe-driven healing, but the 15-min loop with a 1h TTL means up to ~1h of exclusion per cycle.

**3. Contradictions / stale claims**
- A.2: 401 abort "bumps the generation" vs pacing "One `bump_generation` per batch (never per row)".
- C.1: codes-empty 429 → "retryable, no cooldown" vs exhaustion "minimum 10s cooldown".
- Attempt accounting: "total ≤ max_attempts + 2" omits `pool_reuse`, declared "OUTSIDE the key budget" → real bound is `max_attempts + 3`.
- Broken keys "never fail-open candidates" vs fail-open "pick any non-cooling, non-attempted key".
- A.2 default `input_shape` (known) vs C.1 UNCLASSIFIED (one retry) — same response, two classifications.

**4. Missing requirements**
- `failover_max_attempts=0` also kills the 5xx provider retry — a behavioral regression; decouple.
- Probe pacing "provider's known RPM" — source table unspecified.
- No idempotency key on retried upstream calls (duplicate-work note is accepted, but no mitigation).
- `GET /api/entitlements` pagination for 262×N rows.
- Crash backfill race: orphan marking vs a successor row still in the 1s flush buffer (undercount acknowledged but no tie-break rule).

**5. Design notes**
Per-dispatch generation snapshot is the right call — it kills the reload race. `is_terminal` billing is clean but the backfill is the weak seam. Write ownership is correctly one-way (dashboard writes, gateway reads). 429 dual-class via one `entitlement_codes` table is good; empty table = fail-open is the correct boot-order default. Knob clamp at gateway apply-time is warranted. Attempt budget needs one authoritative formula.

**6. Top 5 edits**
1. Reconcile the codes-empty 429 cooldown: pick one (recommend 10s minimum everywhere).
2. State one attempt formula: `1 + failover_max_attempts + 1(provider) + 1(pool_reuse)`.
3. Split A.2's unclassified default from C.1's KNOWN input_shape (distinct `error_code`).
4. Resolve broken-vs-fail-open: broken keys excluded from fail-open too; all-broken terminates.
5. Make generation bumps explicitly per-batch, and only the 401 abort exception.
