**Verdict: GO WITH FIXES** — solid design, but priority-list omissions, regex ambiguity, mock-upstream gaps, and missing observability counters must be addressed before implementation.

**Critical risks**
- Bootstrap starvation: 786-call DashScope bootstrap × 3 keys can exhaust the 5000/day per-provider budget; 25% healing reservation (1250 calls) is thin against daily churn.
- Codes-table-empty 429s default to rate-class (no cooldown); the 10s minimum in the exhaustion contract partially mitigates, but a real balance-dead key still gets hammered across requests until dashboard seeds.
- "Anchored" deny regex is undefined (no `^/$` or `\b` shown); the fallback patterns could match "not activated by request" → false deny → key permanently excluded.
- Per-attempt usage rows multiply by ≤ 1+3+1; non-terminal floods the 1h refresher scan without an explicit `(request_ref, is_terminal)` index plan.
- Streaming 200-then-mid-stream-error: committed at first frame, no retry — accepted but not testable (mock table lacks a stall mode).

**Contradictions / stale claims**
1. A.4 priority list omits `broken` even though A.2 declares broken "priority above balance".
2. A.3 says traffic 200 "promotes to plain ok" but never says it clears `escalated=true` — escalated rows stay input_shape-locked forever.
3. "attempted == pool" (C.1 pool_reuse) is ambiguous: pool = total pool or post-deny candidate pool?
4. `failover_max_attempts ∈ [0, 20]` is dashboard-validated only; gateway belt-and-suspenders is asymmetric with `max_budget_ms`.
5. Grace window (300s) is defined in C.1's "return billing" but never tied back to the 180s ceiling formula.

**Missing requirements**
- Mock modes G (200-then-stall) and slow-TTFB for tests 12, 17.
- Tests for codes-table-empty 429/400 fail-open, codes-table carrier distribution, catalog reload mid-request, escalation lifecycle, janus-auto per-tier snapshot.
- `/stats` counters for `codes_table_loaded`/`version` and `matrix_loaded_at` — the Nodes-page "no matrix" alarm has no metric to read.
- Gateway-side Erlang retry-time classifier ownership/lifecycle (janus_providers vs janus_lb).
- `probe_budget_counters` schema and retention; cooldown-reset semantics on pool_reuse pick.

**Architecture / design notes**
- Per-request deny-map snapshot is correct given ETS atomicity, but janus-auto's tier fan-out across providers shares one snapshot per request — spec is silent.
- Per-attempt usage + `is_terminal` billing gating is clean; legacy backfill (`attempt=1, is_terminal=true`) needs an explicit migration.
- Dashboard-write / gateway-read ownership boundary is clean; the new shared Erlang classifier is the only piece whose repo home is undefined.

**Top 5 concrete edits**
1. **A.4**: priority order `broken > balance > deny > ok` (matches A.2).
2. **A.3**: traffic 200 explicitly clears `escalated=true`; E.1 deny re-admit does the same.
3. **A.2**: define "anchored" (`\b` or full-message); codify in the codes-table seed migration.
4. **C.1**: replace `pool` with `candidate_pool_after_deny` in pool_reuse to remove ambiguity.
5. **Part D / B**: add mock modes G + slow-TTFB; add tests for codes-empty, carrier codes distribution, mid-request reload, escalation; add `/stats` counters `codes_table_loaded`, `matrix_loaded_at`, `matrix_version`.
