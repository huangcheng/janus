**1. Verdict:** GO WITH FIXES — the architecture (dashboard-owned matrix, SQL-only TTL enforcement, snapshot-threaded failover, fail-open escape) is sound, but several internal contradictions and unspecified mechanisms must be resolved first.

**2. Critical risks**
- Probe bursts share rate pools with live traffic: 262 listings × keys at 150ms spacing can itself trigger 429s for paying requests; the cap bounds calls, not rate.
- Ark `InvalidEndpointOrModel` → deny conflates "model doesn't exist" with "key lacks entitlement": one stale listing deny-marks every key → permanent per-request fail-open churn (one wasted attempt per request).
- Retry multiplier: N in-flight requests × pool size during partial outage; no pool breaker (accepted for v1), and fail-open attempts amplify it.
- Ceiling math: 240s budget + 60s TTFB = 300s = idle_timeout *exactly* — "never exceeds" fails at equality; and TTFB=60s is asserted but never defined as a knob or constant the validation can read.
- Streaming: pre-first-byte error-stream collect_drain has no size/duration cap — a slow error body eats the budget.
- Rotation: only deny/balance rows are deleted on secret swap; stale `ok` rows linger (A.4's bootstrap presumably covers this, but A.1/A.4 don't agree explicitly).
- Balance starvation and catalog reload races are adequately handled (45min heal vs 1h TTL; once-per-request snapshot).

**3. Contradictions**
- A.2 opens with "single-flight per provider (in-process lock)" then states "pg advisory lock — the single mechanism; there is no in-process lock."
- 429 RATE-class: "retry another key WITHOUT long cooldown" yet cooling = max(Retry-After, default) — max() makes it longer, not shorter.
- C.1 claims known-broken (401/403) keys are "skipped from candidates entirely", but key-level brokenness is only audited (`entitlement.key_broken`), never shipped in the carrier (deny/balance only) — no gateway mechanism exists.
- "Billing never undercounts" — a crash between upstream 2xx and the row write produces no row at all.

**4. Missing requirements**
- Byte/time bound for the pre-retry error-body drain.
- The TTFB constant the 240000 ceiling derives from.
- SQLite DDL for `key_entitlements` (epoch-int `checked_at`) — only Postgres shown.
- Orphan-row cleanup when listings are renamed/removed.
- Bind-time validation must apply the same TTL downgrades (implied, never stated).

**5. Design notes:** Snapshot-once threading, SQL-as-only-TTL-enforcer, pdict-only loop state (no new gen_server), and promote-only traffic learning (correctly gated on E.1's `error_code`) all respect repo invariants. Attempt accounting (first call unconditional, reserved provider slot outside the key budget, coolest-key reuse) is coherent. Advisory-lock single-flight matches the model-sync precedent.

**6. Top 5 edits**
1. Delete the in-process-lock sentence in A.2; advisory lock only.
2. Ship key-level broken state (or a TTL'd broken-key set) in the carrier, or delete the "skipped from candidates" claim.
3. RATE-class cooldown → min(Retry-After capped, default), matching stated intent.
4. Ceiling: require strict margin below 240000 and define the TTFB source (or validate against listener `idle_timeout` − actual upstream timeout).
5. Add the drain cap, soften the crash "never undercounts" claim, and specify `ok`-row fate on secret rotation.
