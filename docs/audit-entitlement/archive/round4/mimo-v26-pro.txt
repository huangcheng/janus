**1. Verdict: GO WITH FIXES** — sound design (fail-open defaults, TTL windows, generation snapshot threading, per-attempt usage rows), but folded-audit leftovers and two contract holes must be resolved before implementation.

**2. Critical risks**
- **Probe blast radius:** Ark = 135×15 = 2025 calls vs `JANUS_PROBE_MAX_CALLS=1000`; truncation priority ("bound first, then alphabetical") doesn't say per-key vs per-batch — batch-level truncation starves later keys of *all* coverage. Probes share rate pools with live traffic; the 30s provider pause is reactive, not preventive.
- **Deny regex:** scoping to `code`/`message` fields isn't enough — providers echo request/prompt text in `message`; user content containing `未开通` misclassifies as deny. Require provider-owned fields or strip echoed request text.
- **Latency:** budget ceiling 240s + TTFB 60s = 300s = `idle_timeout` exactly — the "never exceeds" claim has zero margin (and Cowboy's idle_timeout is idle-byte-based, so the bound is mis-derived). Ceiling 230s or raise idle_timeout.
- **Retry storms:** no pool breaker; concurrent clients × up to 5 calls against shared rate pools amplifies 429s; 100–300ms jitter is small at concurrency. Rate-class cooling needs `Retry-After` parsing specified.
- **429 dual handling** is right, but BALANCE vs RATE classification reuses the code table — ensure 429 rate-class rows exist in `entitlement_codes`, else all 429s become balance.

**3. Contradictions / stale claims**
- A.2: "single-flight per provider (in-process lock)" vs later "advisory lock … there is no in-process lock." Delete the former.
- C.1: "any byte (including the status line) is forwarded → committed" contradicts "error-status streams … ARE retryable" and deny-shaped-400 retryability.
- The SQLite epoch-seconds variant implies direct gateway-side queries of a table declared dashboard-owned, carrier-read-only — clarify who runs it.
- Part B zero-eligible fail-open ("single attempt") vs C.1 fail-open flag ("at most one per request"): two layers; a request may fail open twice.

**4. Missing requirements**
- **Key-broken state:** 401/403 aborts leave rows untouched + audit `key_broken`, yet C.1 says broken keys are "skipped from candidates" — no status/column exists, and the carrier ships only deny/balance. Define storage+distribution or drop the skip.
- **Secret-swap race:** an in-flight probe holding the old decrypted secret can write rows post-swap (timestamp guard won't help). Tag batches with key secret-version; discard stale writes.
- **Traffic ok-promotion:** does it clear `error_code='input_shape'`? If it re-stamps `checked_at`, the 1h re-probe timer resets forever.
- Flow 19 needs a configurable 5-min grace window; `entitlement_codes` ETS/rebuild path unspecified.

2. Rewrite the commit rule: 2xx or *terminal-classified* response commits; error status lines are drained, never forwarded pre-classification.
3. Add `key_broken` state (column + carrier) or remove candidate-skip.
4. Merge B/C fail-open into one per-request flag and one counter.
5. Tag probe batches with secret-version (stale-write rejection); ceiling → 230s.
