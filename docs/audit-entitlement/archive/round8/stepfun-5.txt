**1. Verdict:** GO WITH FIXES — architecture and failure-mode discipline are sound, but two tables lack DDL, the headline "learning" claim is half-true in v1, and one knob validation is cross-repo impossible as written.

**2. Critical risks**
- Probe blast radius: 786-call bootstrap at 150ms/key pacing is fine per key, but "never more than the provider's known RPM if lower" has no RPM source defined; probes share live rate pools, so a probe-heavy sync can throttle production traffic. Only mitigation is a 30s pause on 429.
- Deny-regex miss = permanent fail-open: v1 traffic evidence only promotes to `ok`. A provider wording absent from `entitlement_codes` seeds → 400 stays unclassifiable → one retry then terminal, forever, until someone hand-edits SQL. That contradicts "maintained by probes plus traffic learning."
- Failover wall time: 45s budget + 60s TTFB + 30s body-cap exceeds common 30s client budgets — admitted, but the ceiling formula is validated at dashboard settings-write against a Cowboy `idle_timeout(300s)` constant the dashboard doesn't own.
- Reload race is properly handled (one snapshot, binary listing-name keys) — but only if client model name == listing name; any translation-layer normalization silently voids the deny map.
- Starvation enforcement is aspirational: bootstrap ≤75% cap "reservations are counters," but nothing guarantees the healing share survives bootstrap consuming first.

**3. Contradictions / stale claims**
- A.3 "traffic refresher" vs v1 ok-only; deny learning is post-E.1, so the motivating bug (LB learns by failing) is only half-fixed.
- B ships a sqlite query after declaring "no sqlite DDL on purpose" — dead weight, delete.
- A.1 gives DDL only for `key_entitlements`; `entitlement_codes` and `probe_budget_counters` are prose-only.
- Broken rows "skipped entirely" vs Part B zero-eligible fail-open: if all keys are broken-marked, is it outage or fail-open? Unspecified.

**4. Missing requirements**
- DDL/columns/constraints for `entitlement_codes` and `probe_budget_counters`, plus the one-time seed SQL location.
- "Known RPM" source.
- Audit-event sink for `entitlement.*`.
- Which current endpoints (embeddings/batch) set `no_failover`.
- Deploy ordering of the gateway migration vs dashboard aggregation change for large `usage_events`.

**5. Architecture notes**
- Single snapshot at `dispatch/7` with fail-open candidates from the same snapshot: correct ETS discipline.
- `is_terminal`-only billing needs explicit dashboard aggregation change + legacy backfill; column-add on a large table warrants a stated ordering.
- 429 dual-class needs body parsing gateway-side; codes-table carrier + empty-table fail-open rule is consistent everywhere.
- persistent_term knob delivery matches repo invariants — only the validation location is wrong.
- Timestamp-guarded upserts across two writers rely on "one DB clock" — true for Postgres, state it explicitly.

**6. Top 5 edits**
1. Add `entitlement_codes` + `probe_budget_counters` DDL and seed-file path.
2. Reword A.3: deny/balance traffic learning is post-E.1; seed gaps fail open until manual codes update — or ship E.1 in v1.
3. Move the budget-ceiling check to gateway apply-time (clamp), or ship `idle_timeout` as a setting.
4. Define "known RPM" (provider field or drop the clause); add yield-on-consecutive-rate-429s.
5. Exclude broken rows from the fail-open pick; delete the sqlite self-question block.
