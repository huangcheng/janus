**Verdict: GO WITH FIXES** — design is sound; several edge cases need pinning down before code lands.

**Critical risks**
- *Budget math vs TTFB*: `failover_max_budget_ms` (default 45s) "gates attempt STARTS" but the **first** call (unconditional) can run its full 60s TTFB past the deadline. With default 45s budget, first attempt may take 105s alone; on tight client budgets operators get silent wall-time overruns. State this explicitly.
- *Deny-regex vs input-shape*: "unsupported operation for this model" / "no permission" classify as `ok+input_shape`, not deny — but providers sometimes use exactly this phrasing for entitlement failures. Unlisted providers will TERMINAL-retry the request (per C.1 input_shape rule) when the phrasing is actually deny. The bug the spec exists to fix hits here.
- *Balance/deny healing starvation*: A.4 caps bootstrap at 75%/day; healing share ≥25%. DashScope-style day-ones (786 bootstrap calls) + 262 deny rows × 3 keys aged ≥22h re-probing = 786 deny re-probes/day, plus per-key balance canaries. If any keys are balance-marked, balance canaries eat healing budget and deny never heals.
- *Streaming first-byte vs mid-stream errors*: spec commits at `stream_reply` and handles "200-then-stall"; Anthropic mid-stream `error` events (200 then error frame) are not classified — exactly the failure pattern chat agents hit.
- *Crash-marking ownership*: spec assigns orphan `is_terminal` backfill to "the usage refresher" (dashboard) but never names the watchdog mechanism (gateway per-request TTL? dashboard scan keyed on `request_ref` age?).
- *Probe-vs-traffic rate contention*: 150ms spacing and 2 keys/provider is fine until a provider's known RPM < probe budget; spec says "never more than known RPM if lower" without a measurement source.

**Contradictions / stale claims**
- A.1 says input_shape-flagged `ok` rows re-probe after **1h**; A.2 premark says they "**never** enter the hourly loop". Pick one — premarked ≠ escaped-from-healing.
- C.1 exhaustion says "**last** received error returned" but provider-retry exhaustion says "return the **best** error". Same path, different rule.
- `ok` rows "never ship to gateways" but the deny-map only excludes bad keys; no symmetry for "known-good key steering" (acknowledged as design but worth flagging).

**Missing requirements**
- "Best error" disambiguation (last? first? lowest latency?).
- `probe_budget_counters` schema not specified.
- Refresher watchdog mechanism + scan cadence.
- Probe-classified `__key__` row TTL vs deny (both 24h — broken keys may auto-recover silently).
- Old `key_entitlements` rows never cleaned (table grows forever).
- New-provider codes seeding workflow post-launch (defaults fully fail-open — confirm intentional).

**Architecture notes**
ETS snapshot at `dispatch/7` entry is correct; `now()`-at-query-time TTL is the only gate (no gateway-side recheck) — sound. Per-attempt usage rows with `is_terminal` flag and dashboard counting `WHERE is_terminal` is the right billing primitive. Dashboard/gateway write split clean. Persistent_term knob delivery correct.

**Top 5 concrete edits**
1. Document first-call TTFB can exceed `failover_max_budget_ms`; raise default to ≥ 60_000 or split "first-call budget" from "retry budget".
2. Add deny candidate when message matches "unsupported operation for this model" *and* codes table has no input_shape row for that provider — treat as UNCLASSIFIED (one retry), not input_shape TERMINAL.
3. Resolve A.1/A.2 input_shape-loop contradiction: premark skips initial probe only; 1h healing schedule still applies.
4. Replace "best error" with "last received error" everywhere; define last = attempt with highest non-terminal `attempt` index.
5. Specify crash-marking as gateway-side: cowboy handler exit posts `is_terminal=true` on buffered rows via janus_usage cleanup; dashboard refresher is fallback after 300s grace.
