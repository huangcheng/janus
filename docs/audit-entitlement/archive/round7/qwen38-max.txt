**1. Verdict**
GO WITH FIXES — the architecture (dashboard-owned matrix, SQL-enforced TTLs, per-request generation snapshot, budget-capped failover) is sound, but one core retry semantic contradicts its own test plan and two lifecycle mechanics are undefined.

**2. Critical risks**
- **Probe cost/blowback:** a 262-listing bootstrap cannot finish under the 10-min wall cap at 15s timeouts (~40 calls max); no resume rule. Hourly `input_shape` re-probes can exceed the 5000/day budget unless pre-marked modality rows are excluded — the exclusion mechanism is unspecified.
- **Deny-regex vs input-shape:** C.1 grants "ONE failover attempt" to input-shape/unclassifiable 400s while test 8 demands zero retries — the behavior for the most common production 400 is undefined.
- **Latency vs idle_timeout:** ceiling math checks out (180 ≤ 300−60−30−30), but the 45s default knowingly busts 30s client budgets; no per-route override.
- **Retry storms:** bounded per request, cooling damps bursts; but provider-slot reuse when `attempted == pool` and *no* key is cooldown-expired is undefined.
- **Reload races:** single snapshot at `dispatch/7` entry resolves mixed-generation picks; ETS atomic swap is compatible.
- **Balance starvation:** well handled (1h TTL, 15-min canary, ≥25% reserved share); canary model selection rule missing.
- **Rotation:** secret-wipe + re-probe queue is sound; broken-key detection is only as fast as probe cadence — between probes a dead key costs one failover per request (acceptable, unstated).
- **Streaming boundary:** commit at `stream_reply`, error-status `collect_drain` retryable — precise and correct.

**3. Contradictions / stale claims**
1. C.1 (input-shape/unclassifiable 400 → one failover) vs test 8 (input-shape → NO retry).
2. A.2 pre-marked modality rows "never enter the hourly loop" vs A.1 `input_shape`-flagged `ok` re-probed after 1h.
3. Probe 429 backoff: "halve in-flight 30s" vs "pause that provider's probe 30s".
4. A.2 "single-flight (in-process lock)" vs "advisory lock is the single mechanism".
5. E.5 rows ≤ attempts+1 vs C.1 total ≤ max_attempts+2 calls.

**4. Missing requirements**
Bootstrap truncation/resume semantics; balance canary selection; classifier matching semantics (substring/regex/case, which fields) plus Python↔Erlang parity fixtures; orphan `request_ref` backfill scan/query; `broken` count in probe response; SQLite carrier behavior stated as "skip silently" (the illustrative SQL invites misimplementation).

**5. Architecture notes**
Snapshot-per-request reads vs atomic ETS rebuild: correct. `is_terminal`-only billing undercounts real upstream cost (prefilled tokens on failed attempts) — state this divergence explicitly. Write ownership is clean; the one-source `entitlement_codes` table is right, but dual-language classifiers are the divergence risk. 429 dual-class with fail-open-on-empty default is correct. Knobs via settings→persistent_term match repo invariants.

**6. Top 5 edits**
1. Split C.1: classified `input_shape` 400 → terminal; only *unclassifiable* 400 → retry-once. Fix test 8 or C.1 accordingly.
2. Write pre-marked modality rows with `escalated=true` so A.1's hourly rule skips them.
3. Define truncated-bootstrap resume (bound-first priority persists across batches).
4. Correct E.5 to attempts+2; specify canary selection (bound/cheapest model) and provider-slot pick when all keys still cooling.
5. Add classifier parity E2E: identical EN+CN fixtures run through both Python and Erlang classifiers.
