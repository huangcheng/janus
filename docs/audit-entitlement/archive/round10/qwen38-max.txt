**1. Verdict:** GO WITH FIXES — the hard parts (TTLs, latency ceiling, commit boundary, generation snapshot) are sound; four concrete consistency bugs and two unenforced claims remain.

**2. Critical risks**
- **Probe vs live-traffic rate isolation:** probes go direct to upstream, bypassing janus_lb, so A.2's "probes share rate pools with live traffic" has no mechanism. A 786-call DashScope bootstrap can trip provider RPM and 429 real clients; only mitigation is reactive 30s pauses.
- **input_shape flapping:** hourly re-probes send the generic "hi" shape, which 200s and promotes `input_shape` rows to `ok`; real traffic then fails identically, but v1 traffic evidence can't demote → false-ok churn + burned budget.
- **Retry storms:** ≤ max_attempts+2 upstream calls per request during pool-wide outage; per-key cooling lags concurrent bursts (no pool breaker, acknowledged) — amplification factor never quantified.
- **Failover latency:** worst case ≈270s at the 180s ceiling fits idle_timeout(300s) with thin margin; default 45s budget explicitly strands 30s-budget clients (accepted, stated).
- **Rotation staleness:** "gateways drop the stale broken mark immediately" is bounded below by the poll interval — not immediate.
- **Streaming boundary** (commit at `stream_reply`; error-status streams collected pre-byte are retryable) is correct.
- Deny-regex guards (anchored, code/message-only, `no permission` ≠ deny) are adequate; residual risk is operator-edited regexes with no fixture regression gate.

**3. Contradictions / stale claims**
- **E.5 vs C.1 off-by-one:** E.5 says rows multiply "≤ (attempts+1)"; C.1 says "total ≤ max_attempts + 2" (first + retries + reserved provider slot). Default 3 → E.5 says 4, C.1 says 5.
- **Test 10 is incoherent:** "all keys deny-marked, matrix stale" cannot trigger fail-open — stale rows fail the carrier TTL SQL and never ship, so candidates are never emptied. Must be fresh-but-wrong marks.
- A.2's "shared rate pools" claim is unimplemented cross-repo.

**4. Missing requirements**
- E.6's matrix-less alarm needs a `/stats` field (`matrix_generation`/`matrix_loaded`) absent from C.1's fixed counter list.
- Response when `pg_try_advisory_lock` is busy (409? 202?) unspecified.
- `escalated` reset scope on `entitlement_codes` edits ("affected rows") undefined.

**5. Architecture notes**
- One generation snapshot per request cleanly solves reload races; dashboard-only write ownership is correct; SQL-side TTL enforcement avoids gateway drift; single codes table driving probe/refresher/retry is the right call. Per-attempt usage rows with `WHERE is_terminal` billing is clean, pending the E.5 fix.
