**1. Verdict:** GO WITH FIXES — the design is sound, but a deploy-order contradiction, an unspecified codes-table schema, and per-request deny-map copying must be resolved first.

**2. Critical risks**
- **Probe blowback:** probes share provider RPM with live traffic; pacing says "never more than the provider's known RPM if lower" but never defines RPM's source — a wrong/absent RPM throttles production.
- **Deny-regex false positives:** mitigated (anchored, fail-open, `no permission`→input_shape), yet a genuine deny phrased unusually becomes input_shape → terminal → no failover: the motivating bug persists for that provider.
- **Failover latency:** 45s default already admitted to break 30s clients; ceiling math stacks budget + TTFB + 30s body-cap + jitter.
- **Retry storms:** only per-key cooling; concurrent bursts on a shared pool still fan out. Empty-codes 429's 10s cooldown is the sole global damper.
- **Reload races:** handled well (one snapshot at `dispatch/7`).
- **Balance starvation:** 1h TTL + 15-min healing loop, but the key-scoped canary fires only when `key_scoped_balance` is true.
- **Rotation:** rows deleted + generation bumped — good.
- **Streaming boundary:** committed at first byte / `stream_reply`; error-status streams collected pre-byte — consistent.

**3. Contradictions**
- Part E DEPLOY ORDER ships E.3 (dashboard aggregation `WHERE is_terminal`) BEFORE E.2 (gateway adds that column) — aggregation queries a nonexistent column.
- A.2 response `{ok,deny,balance,skipped}` omits `broken` (the 401 abort) and `unknown`, though both are written.
- pool_reuse wording: C.1 "cooldown-EXPIRED, least-recently-used" vs test 16 "coolest key".
- `entitlement_codes` is referenced throughout; its DDL/outcome enum never appears.

**4. Missing**
- `entitlement_codes` schema + `outcome` values; how `key_scoped_balance` is set; RPM source; zero-listing provider behavior; probe endpoint rate limits; `/stats` counter reset semantics; usage_events `attempt/request_ref/is_terminal` DDL.

**5. Architecture notes**
- `deny_keys` copied per request is O(keys×models) — prefer keyed ETS lookups.
- Per-attempt rows + `is_terminal` billing is correct; crash-marking backfill sound, but row volume ×(attempts+1).
- Write ownership clean (dashboard sole writer; gateway reader-only).
- Empty-codes default (all 429=rate) risks storming balance-dead keys — 10s cooldown is thin.

**6. Top 5 edits**
1. Fix deploy order, or make E.3 aggregation null-safe.
2. Ship `entitlement_codes` DDL + outcome values; add `broken`/`unknown` to probe counts.
3. Define RPM source; default probe pacing to a safe floor.
4. Unify pool_reuse/LRU wording and its ordering vs the provider-retry slot.
5. Replace per-request deny-map copy with keyed ETS lookups.
