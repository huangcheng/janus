## 1. Verdict
**GO WITH FIXES** — sound architecture, but the deny-regex classification, retry-vs-Cowboy-timeout math, and 429 dual-meaning handling need tightening before implementation.

## 2. Critical risks

- **Deny-regex false positives vs input-shape 400s**: the deny list (`not activated|no permission|invalid endpoint|not entitled|unsupported operation`) and "input_shape → ok" share the same 400 space. Upstream wording varies (e.g. Ark's Chinese error bodies, DashScope `InvalidParameter` on model-gated features). A real deny that misses the regex becomes `ok` and defeats the pre-filter; an input-shape 400 matching the regex becomes `deny` and wrongly poisons routing. Needs per-provider test vectors in flow 1.
- **Failover latency vs Cowboy idle_timeout**: 3 attempts × 60s TTFB worst-case = 180s, but listener `idle_timeout` is 300s and streaming bodies inherit different paths — the spec's "bounded by attempts × TTFB" hand-waves accumulated connect + drain time. Retry storm risk when a provider-wide outage maps 429s across all keys: N concurrent requests × 3 attempts = 3× upstream hammering with no jitter/backoff specified.
- **Probe blowback**: 5 concurrent × max_tokens=1 probes can trip provider-side rate limits, polluting the matrix with `skip` (leaving stale `ok` rows) and worse, triggering fraud/anti-abuse flags on real accounts. No pacing/ramp or global per-provider daily budget is specified.
- **Balance-key starvation**: `balance` treated as deny-until-refreshed, but nothing in v1 refreshes it — a key topped up stays excluded until the 7d TTL or a manual re-probe. Missing requirement.
- **Key rotation staleness**: rotating a key's secret keeps the same `provider_key_id`, so old entitlements (deny rows from the old secret) persist and wrongly pre-filter the new key for up to 7 days.

## 3. Contradictions / stale claims

- C.1 says "balance entries are also excluded (they fail over once, learn, and become deny-refreshable)" — but traffic learning (A.3) only maps 400/404 → deny; 429-balance → deny promotion is undefined. Contradictory.
- A.1 says `source='traffic'` rows are "written by the gateway (Part C)", but Part C never has the gateway writing entitlements; A.3 puts the refresher in the dashboard. Stale claim — the gateway must never write dashboard-owned tables.
- D flow 12 tests bind validation, but A.5's "binding … is rejected" lacks any API/behavior spec (error code, override path).

## 4. Missing requirements

- Passive learning's deny classifier needs the upstream **error text** — `usage_events` today has status only, "no error text". The spec silently assumes a recorded "error shape" that doesn't exist; a schema/capture change is required and unlisted.
- No idempotency/upsert semantics for concurrent probe + traffic writes (last-write-wins on `checked_at` stated for traffic only, not probe-vs-probe).
- `failover_max_attempts` knob delivery: sys.config vs `settings` table (persistent_term distribution) unspecified — violates the project's own config-flow invariant if ambiguous.
- No retry-attempt annotation in usage rows (attempt #, failover flag) — billing/observability gap for double-charged-looking rows.

## 5. Architecture / design notes

- ETS rebuild atomicity is fine (catalog swap is atomic), but probe write → `bump_generation` → poll lag means the matrix is seconds stale; failover loop must tolerate racing cooldown entries — acceptable, but spec should say so.
- Per-attempt usage rows are correct but need an attempt dimension or the A.3 refresher will count failover-internal 4xx as traffic evidence for the *requesting* key's sibling keys ambiguously.
- 429 dual meaning (rate vs balance) is classified by text regex twice (probe and runtime) — centralize the regex, ship it in the spec once.
- Attempt budget: "more eligible keys remain" + max 3 needs explicit interaction with pool size 1–2.

## 6. Top 5 concrete edits

1. Add `usage_events.error_code/error_text` capture as an explicit prerequisite task for A.3.
2. Specify key-secret rotation → invalidate entitlement rows for that `provider_key_id` (on key update, delete rows).
3. Define balance-refresh path (probe re-check or TTL to `unknown`, never silent permanent exclusion); resolve the C.1/A.3 429-promotion contradiction.
4. Add pacing (e.g. 1 rps/key ramp) and a probe cost/rate budget knob; document deny-regex per-provider fixtures in flow 1.
5. State knob delivery via `settings` table + persistent_term, and cap total failover wall time explicitly against the 300s idle_timeout (e.g. attempts share one deadline).
