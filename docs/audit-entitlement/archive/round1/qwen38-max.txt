**1. Verdict**
GO WITH FIXES — architecture is sound (matrix rides the existing catalog carrier, failover is bounded), but traffic-based deny learning is built on evidence `usage_events` doesn't carry, and excluded keys can never self-heal.

**2. Critical risks**
- Deny regex is English-only; DashScope/Ark/zhipu emit native error text → real denies misread as `ok/input_shape`. "unsupported operation for this model" in the deny regex often means modality mismatch → re-ships the uni-api bug. "Throttle concurrency" on rate-limit 429 is undefined. "2–4 min" sweep is stale: 786 reqs ÷ 5 concurrency × 15 s timeout ≈ 40 min worst case.
- **Starvation loop**: deny/balance keys are excluded from picking → receive no traffic → passive learning never sees a 200 → stuck until a manual probe. Deny persists up to 7 days after a provider-side re-enable (A.4 only re-probes >7d rows).
- Retry storm: a provider-wide 401/403 triples upstream load before cooling learns anything; no global budget or breaker.
- Latency: 3×60 s = 180 s fits Cowboy's 300 s idle_timeout but exceeds typical client timeouts; retry behavior after client disconnect is undefined.

**3. Contradictions / stale claims**
- A.1 says the *gateway* writes `source='traffic'` rows; A.3/C.1 say the dashboard folds usage rows; the boundary section says matrix storage is dashboard-owned. Pick one writer.
- A.3 folds deny from "the recorded error shape," but usage_events has **no error text** — status-only deny cannot distinguish deny-400 from input-shape-400, the exact bug the spec warns about.
- A.3 freshness compares `checked_at`, but folding stamps `checked_at=NOW()` at fold time, so stale events re-folded later permanently outrank newer probe oks. No event watermark.
- C.1 never says whether the 5xx "one extra attempt" consumes the 3-attempt budget.

**4. Missing requirements**
- `key_entitlements` is dashboard `ensure_schema`, yet the gateway bundle query runs at boot — fresh or re-ordered deploys hit a missing table. Needs a gateway migration or tolerant fetch.
- Delivery path for `janus.failover_max_attempts` (settings table → persistent_term per repo invariants, not sys.config).
- How judge calls flag no-failover inside `do_proxy`.
- Client-disconnect abort; key-secret rotation invalidation; one generation bump per probe batch, not per row.

**5. Architecture/design notes**
- ETS carrier shape is fine; pre-filter must only test the picked provider's candidate keys (cross-provider model-name collisions are harmless solely via global key-id uniqueness).
- Per-attempt usage rows skew success-rate metrics and get re-fed to the folder — watermark/dedup needed.
- ETS swap between attempt 1 and 2 of one request is benign but should be stated.

**6. Top 5 concrete edits**
1. Restrict traffic learning to `ok` promotion until usage_events carries error text; never status-only deny.
2. Fix write ownership: gateway never writes `key_entitlements` (rewrite A.1).
3. Shorter recheck TTL (≤24 h) for deny/balance + post-top-up probe; document the starvation loop.
4. Unify attempt accounting (5xx consumes the same budget), abort retries on client disconnect, ship the knob via the settings table.
5. Classify on provider-native error codes first; move "unsupported operation" to the input-shape branch.
