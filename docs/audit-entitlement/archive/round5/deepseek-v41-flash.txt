**1. Verdict:** GO WITH FIXES — the design is sound and unusually well-instrumented, but several cross-section contradictions (key-broken state, 429 cooldown, sqlite DDL) must be resolved before implementation.

**2. Critical risks**
- Probe cost/blowback: 1000-call/provider daily budget shared across sync+bootstrap+healing; DashScope 262×3 keys = 786 in one sync, starving healing. Probes hit live rate pools.
- Deny-regex FP: fail-open default (400→ok+input_shape) + code-table-first is right, but `no permission` → ok while some providers genuinely gate on it; no per-provider override.
- Failover latency: budget+TTFB = 270s at ceiling, under 300s idle_timeout — OK; default 45s already exceeds many client timeouts.
- Retry storms: per-key cooling only; concurrent bursts retry in lockstep (100–300ms jitter marginal).
- Reload race: per-request snapshot threading is correct.
- Balance starvation: A.3 can't heal (no traffic); healing loop is sole path and shares the budget.
- Rotation: row deletion on secret change is correct.
- Streaming boundary: error streams collect_drain→retryable; 2xx committed at stream_reply — correct.

**3. Contradictions / stale claims**
- C.1 "known-broken key (401/403 probe evidence) skipped from candidates" — no such state exists: A.2 leaves rows untouched and 401 isn't a status. Gateway cannot know.
- A.2 "unlisted provider defaults to rate-class (retry, no cooldown)" vs C.1 rate-class cooling = max(Retry-After, default) — which benches a healthy key, contradicting "not benched by one burst."
- `stable_input_shape` violates the status CHECK ('ok','deny','balance','unknown'); storage unspecified.
- A.1 "probe writes unknown rows lazily" vs A.2 classifying unclassifiable 400 as `ok`; unknown lifecycle undefined and healing never targets unknown.
- Deny map keyed by ModelName only (B) — no provider scope; same listing name across providers merges keys.
- Two fail-opens (B zero-eligible vs C.1 attempted-empty) with unspecified interaction.

**4. Missing**
- Index on request_ref/is_terminal for backfill + `WHERE is_terminal` billing.
- Legacy backfill strategy (full-table UPDATE unspecified).
- `failover_max_attempts=0` semantics for the reserved provider retry.
- sqlite DDL (A.1 schema is Postgres-only; TIMESTAMPTZ/NOW() invalid in sqlite).
- Bind validation for `balance` listings; provider-retry behavior with deny map loaded.

**5. Architecture notes**
Snapshot-once + per-attempt rows are right. Write ownership clean. Budget accounting correct except the 0-case. Knob ceiling hardcodes 300s at dashboard write time — drifts from listener config. 429 dual-class handled but cooldown contradictory. Crash backfill needs the request_ref index.

**6. Top 5 edits**
1. Add a persistent key-broken signal (status/column) or delete the C.1 claim.
2. Key the deny map by {Provider, ModelName}.
3. Reconcile 429 cooldown (A.2 vs C.1) and 0-attempt provider-retry.
4. Specify sqlite DDL, unknown-row lifecycle, stable_input_shape storage.
5. Add request_ref/is_terminal indexes + backfill strategy; define fail-open interaction.
