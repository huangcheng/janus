**1. Verdict:** GO WITH FIXES — the design is coherent and unusually failure-mode-aware, but the request-time classifier contradicts the spec's own fail-open philosophy, and the daily probe budget can be monopolized by one bootstrap.

**2. Critical risks**
- Unclassifiable 400 is terminal at request time (C.1) but `ok` at probe time (A.2 §3): the exact motivating production case (deny wording from an unlisted provider) still reaches the client with zero failover. Biggest risk in the doc.
- Budget starvation: DashScope 262 listings × 3 keys ≈ 786 calls vs `JANUS_PROBE_MAX_CALLS=1000` daily — one full bootstrap leaves ~214 for healing; A.4's "no trigger starves another" is false as written.
- Retry herd: cooling benches only failed keys; N concurrent requests converge on the one healthy key (flow 4's key B), amplified by client-side retries. No pool-level breaker in v1.
- Grace knife-edge: crash-marking grace is 5 min; max wall ≈ 210s budget + 60s TTFB + jitter ≈ 271s. Holds only while the ceiling formula is respected — nothing links the two.
- Sqlite gap: the gateway may read sqlite, but only the dashboard's (postgres) `ensure_schema` creates the table; undefined-table tolerance means sqlite gateways silently run matrix-less forever.

**3. Contradictions / stale claims**
- A.2 "a false `ok` costs one failover attempt" vs C.1 "non-deny 400 → return immediately": a false ok costs a client-visible failure, not a failover attempt.
- Part B retains a drafting artifact ("Both dialect variants ship as gateway migrations? No —").
- RATE-class "retry WITHOUT long cooldown" yet cooling = `max(Retry-After, existing default)` — that is at least the default cooldown; contradiction unless the default is short and stated.

**4. Missing requirements**
- `attempt`/`is_terminal` values for janus-auto judge rows (bypassing the loop) unspecified.
- No failover observability beyond the fail-open counter (attempts-per-request histogram, retry rate).
- Bind-time validation is one-shot; later deny flips never re-warn bound routes.

**5. Architecture / design notes**
- Snapshot-at-dispatch threaded through attempts + atomic generation swap is correct; binary-keyed deny map closes the known bug class.
- `is_terminal`-only billing with crash backfill of flushed rows is sound; the 1s-buffer loss bound is honestly stated.
- `entitlement_codes` as the single classifier source (probe, refresher, gateway retry) via the carrier is the strongest part of the design.
- Knobs via settings → persistent_term respect the repo invariant; ceiling validation at write time is good.

**6. Top 5 concrete edits**
1. C.1: make unclassifiable 400/404 retryable once (then terminal), restoring A.2's fail-open asymmetry at request time.
2. A.4: reserve a healing share (e.g., ≥25%) of the daily probe budget so bootstrap can't idle it.
3. State sqlite ownership explicitly: dashboard ensures schema there, or declare the matrix postgres-only by design.
4. Define the RATE-class cooldown default numerically; fix the "without long cooldown" sentence.
5. Codify `grace ≥ ceiling + TTFB + jitter` as a validated invariant beside the ceiling check; delete the Part B rhetorical fragment.
