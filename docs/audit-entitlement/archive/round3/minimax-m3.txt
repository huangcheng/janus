**1. Verdict:** GO WITH FIXES — sound design, but five concrete gaps (notably the `ok` TTL is never enforced and the streaming-committed boundary is fuzzy).

**2. Critical risks:**
- **Deny-regex false positives vs input-shape 400s** — default fail-open costs one failover attempt; that's acceptable, but `unsupported operation for this model` on some providers IS deny evidence; "NOT deny by themselves" risks misclassification. Add positive deny examples per provider, not only negative.
- **Probe cost & rate-limit blowback** — 150ms × 262 listings × 3 keys ≈ 2 min, but fine-tune tier (e.g., DashScope free tier) caps at ~10 RPS; the batch self-DoSes. The 30s pause handles mid-batch 429s, not pre-batch pool exhaustion.
- **Failover latency vs idle_timeout** — 280s ceiling < 300s is correct, but worst-case 45s + 60s TTFB = 105s already eats >40% of common client budgets; first-byte slow-but-succeeds paths will be abandoned.
- **Retry storms** — 429 cooldown treats rate-limit identically to balance (point 5 below).
- **Matrix/catalog reload races** — per-request snapshot is correct; not explicit for streaming responses that span the reload.
- **Balance-key starvation** — bounded by 1h TTL, OK.
- **Key rotation staleness** — gateway reads NEW secret but matrix rows describe OLD secret until re-probe completes; window of misclassification.
- **Streaming first-byte boundary** — "any byte including status line" vs the existing `Status >= 400` collect_drain path are fuzzy.

**3. Contradictions / stale claims:**
- `ok` TTL (7d; 1h for input_shape) is **never enforced anywhere** — gateway never reads ok rows, and the healing loop only refreshes deny/balance. Nothing re-probes aging ok rows.
- "Committed = status line OR 2xx" conflicts with the Status-collect-drain retryable path unless "forwarded to the client" is precisely defined.
- "checked_at — evidence time (NOT fold time)" — `fold time` is undefined jargon.

**4. Missing requirements:**
- What triggers re-probe of an aging `ok` row? (not sync, not key event, not healing loop.)
- Probe batch concurrency safety vs concurrent `/api/models/sync` (advisory lock scope unclear).
- Per-attempt usage rows: `request_ref` is UUID, but cross-process aggregation/joins need an index hint or a per-process namespace rule.
- `janus_entitlement_failopen` counter lacks a circuit-breaker (recurring fail-open = stale matrix, no auto-stop).
- Anthropic thinking-token models: `max_tokens=1` may be invalid for thinking surface; probe shape per protocol needs more than `max_tokens`.

**5. Architecture/design notes:**
- ETS rebuild atomicity + per-request snapshot is the right primitive; persist as-is.
- `WHERE is_terminal` billing is correct; flag that legacy backfill must run before any analytics migration deploys.
- Dashboard-writes / gateway-reads ownership is clean.
- 429 dual meaning is correctly collapsed for routing but conflated for cooldown.
- Attempt-budget accounting (1 + K + 1) is clear.
- Knob delivery via persistent_term with settings-write validation ≤ 280000 is correct.

**6. Top 5 concrete edits:**
1. **Define what re-probes an `ok` row when 7d elapses** (extend healing loop, OR ship ok-rows with TTL in the carrier and let the gateway re-classify to `unknown`).
2. **Tighten "committed"**: a request is committed iff any byte has been passed through `gun:ws_send`/`cowboy_req:reply` to the socket. Status known but buffered upstream = not committed; collect_drain-then-retry stays legal.
3. **Distinguish 429 rate-limit vs 429 balance at cooldown**: rate-limit skips cooldown (move on, do not penalize the key); balance keeps current cooldown.
4. **Rotation matrix-staleness**: while a key's re-probe is queued/in-flight, the gateway treats its deny/balance map entries as `unknown` (eligible) to avoid misrouting a key whose secret may now belong to a different account.
5. **Probe pacing must respect provider rate class**: pull RPS from the existing provider config (already known for routing) and set per-batch concurrency ≤ `min(provider_rps, 2)`, not a flat "≤ 2 keys".
