## 1. Verdict
**GO WITH FIXES** — the design is sound and unusually well-hardened, but the budget-ceiling math violates the Cowboy idle_timeout invariant, and A.2 contradicts itself on locking.

## 2. Critical risks
- **Failover latency vs idle_timeout (real bug):** worst-case wall = budget + one TTFB. Ceiling 280s + TTFB 60s = 340s > Cowboy 300s — exactly the bodiless-502 failure the spec claims to avoid. Ceiling must be ≤ 240s (or idle_timeout − max TTFB).
- **Probe cost:** 262 listings × 150ms + TTFB ≈ 90–120s/key; 2-key parallelism fits the 10-min target, but `JANUS_PROBE_MAX_CALLS=1000` is per-batch while the healing loop (hourly) and sync-triggered probes share it — starvation between triggers unaddressed.
- **Deny-regex false positives:** fail-open default is correct, but classifying `no permission` as `ok/input_shape` means real denies phrased that way are *never* learned — ok rows with input_shape expire in 1h, so these keys get re-probed hourly forever. Acceptable, but unquantified (probe spend).
- **Retry storms:** up to 5 upstream calls per client request; under a provider-wide key outage, every request amplifies load ~4× with only 100–300ms jitter. Cooldowns help across requests; nothing damps concurrent in-flight retries.
- **Rotation staleness:** secret update keeps old rows "until fresh evidence" — a prior account's `deny` rows exclude the new secret for the re-probe gap (up to hours if probe queue is saturated). Deny rows should be dropped/quarantined at secret-write time.
- **Balance starvation:** handled correctly (1h TTL + healing loop).

## 3. Contradictions / stale claims
- A.2: "Single-flight per provider (in-process lock)" vs. later "Postgres advisory lock … **not** an in-process lock." Pick one (advisory).
- "The SQL is the ONLY TTL enforcement point" yet A.1 specifies 7-day/1h `ok` TTLs — `ok` is never shipped, so those lifetimes have no enforcement point at all; only UI/refresher semantics.
- Tests 11 and 16 are the same test.
- SQLite carrier: `strftime('%s',…)` returns TEXT; `checked_at > '…text…'` with INTEGER affinity always compares false in SQLite's type ordering — the TTL silently breaks. Needs CAST or uniform storage.

## 4. Missing requirements
- usage_events write amplification (3–5× rows) — no batching/backpressure note for `janus_usage`; no index spec for the refresher's 1h scan window.
- `entitlement_codes` carrier encoding in the bundle is unspecified (shape, versioning).
- Probe URL construction for anthropic (base already ending in `/v1` → duplicate segment risk).
- No probe concurrency limit *across* providers (per-provider limits only).
- Fail-open counter has no alerting/telemetry requirement.

## 5. Architecture notes
Snapshot-at-entry for the deny map is correct and consistent with the ETS generation swap; per-attempt usage rows with `is_terminal` aggregation is clean; dashboard-only write ownership holds; 429's dual meaning (rate vs balance) is correctly split at classification but both are key-retryable at failover time — acceptable. Knob delivery via persistent_term follows the repo invariant.

## 6. Top 5 concrete edits
1. Lower budget ceiling to ≤240000ms (idle_timeout − TTFB) and add test 12-variant at the ceiling.
2. Delete the "(in-process lock)" clause in A.2.
3. Fix the SQLite TTL comparison (CAST or integer literal arithmetic).
4. On secret update, delete that key's deny/balance rows immediately instead of waiting for re-probe.
5. Merge tests 11/16; add usage-writer amplification + scan-index requirements to Part E.
