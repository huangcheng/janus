## 1. Verdict
**GO WITH FIXES** — the fail-open biases, committed-response rule, and advisory-lock single-flight are right, but stale-`ok` healing is missing and several claims are stale.

## 2. Critical risks
- **Probe cost/blowback:** 262 listings × 3 keys × 150ms ≈ 2 min/provider; sync-triggered probes queue across providers and can burst past the 1000-call/10-min envelope; a 30s 429 pause makes the wall target unmeetable, and probes share live rate pools — provider-wide 429s can cascade into real traffic.
- **Deny-regex FP:** fail-open default is right, but the regex scans whole bodies; provider text containing "not activated"-class phrases (docs, tool traces) misclassifies — scan only error code/message fields.
- **Latency:** 45s + 60s TTFB exceeds typical 30–60s client budgets — failover often finishes after the caller abandons (money spent, response dead).
- **Balance starvation:** excluded keys get zero traffic; only the hourly loop heals. Dashboard down >1h → rows expire → keys re-enter and burn one failover attempt per request.
- **Rotation:** rows persist pre-re-probe; a re-secreted key from a different account silently inherits stale exclusions.
- **Retry storm:** N concurrent 503s → 2× upstream load; spec never confirms cooldown/breaker absorbs it.

## 3. Contradictions / stale claims
- A.1's "expired row = consumer-downgraded at read time (Part B windows)" is false — Part B SQL is the *sole* TTL point; gateways never see expired rows.
- A.2 opens with "in-process lock" then corrects to advisory lock; delete the first.
- C.1's per-iteration "drop the deny-map exclusion" fail-open contradicts B's *single* fail-open attempt — up to `max_attempts` fail-opens per request otherwise.

## 4. Missing requirements
- **No re-probe path for aging `ok` rows** (healing loop covers only balance/deny): a key that loses entitlement stays first-choice for 7 days, paying one wasted attempt per request.
- No byte bound on regex-scanned body; negative fixture corpus underspecified (D flow 1 lists positives only).
- No failover metrics beyond the failopen counter.
- No stated invariant that key-scoped retries duplicate zero upstream work (401/403/deny/balance-429 never execute) — make it explicit; only 5xx/timeout risks duplication.
- Model deleted between listing-fetch and probe → junk row; specify skip.

## 5. Architecture notes
- ETS generation swap + per-request snapshot is sound; carrier binary listing names must match LB keys exactly.
- `is_terminal`-only billing is correct, but legacy backfill and column defaults must ship in the *same* migration as Part C.
- 429 dual meaning: at gateway both are key-scoped (right), but a rate-limited key cools as long as a broken one — differentiate.
- Attempt math (1 + max + 1 reserved) is unambiguous; knob delivery via persistent_term matches the repo invariant.

## 6. Top 5 edits
1. Add scheduled re-probe of `ok` rows older than ~3 days (or cut ok TTL to 72h) in A.4.
2. Fix A.1/B TTL wording: SQL-enforced only; strike "consumer-downgraded."
3. Restrict classifier regex to `error.code`/`error.message`; add multilingual negative fixtures.
4. Drop default `failover_max_budget_ms` to ~25s; document the client-abandonment tradeoff.
5. Fail-open once per request (not per loop iteration); add per-class failover counters.
