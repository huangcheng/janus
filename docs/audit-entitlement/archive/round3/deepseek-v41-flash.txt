## 1. Verdict
**GO WITH FIXES** — the design is sound and unusually self-aware (fail-open, TTLs, starvation loop), but the budget ceiling is arithmetically wrong and several enforcement boundaries are double-claimed.

## 2. Critical risks
- **Budget vs idle_timeout (real bug):** ceiling 280s is justified as "< 300s", but a call *started* inside the deadline may run a full 60s TTFB → 280+60=340s > Cowboy `idle_timeout` 300s → bodiless 502. Ceiling must be ≤ 300s − TTFB (~240s).
- **429 dual meaning:** Part C treats *any* 429 as key-scoped and cools the key. A transient rate-limit 429 then cools a healthy key and moves load to siblings that are also rate-limited → retry storm and false cooldowns. Rate-limit should not demote/retry as key-scoped.
- **Balance starvation:** balance keys get zero traffic for up to 1h; only the hourly healer recovers them. If the pool is small, effective capacity drops silently.
- **Rotation staleness:** "rows stay until fresh evidence arrives" means a rotated key with a valid new secret can stay deny-excluded for up to 24h.
- **Deny-regex false positives:** mitigated by fail-open/input_shape default — acceptable — but `ok+input_shape` rows expiring at 1h vs 7d is inconsistent with them never shipping.
- **Reload race:** "attempts never mix generations" is asserted but `dispatch/7` re-picks per iteration; the snapshot must be threaded explicitly.

## 3. Contradictions / stale claims
- A.1: "consumers enforce by `checked_at`" vs B: "SQL is the ONLY TTL enforcement point."
- C.2 ceiling rationale (280s < 300s) is false once TTFB is added.
- `ok+error_code='input_shape'` 1h TTL is moot (ok rows never ship).
- Test 16 duplicates Test 11.

## 4. Missing requirements
- Which error is returned on key-scoped exhaustion (only 5xx "best error" is defined).
- Crash mid-loop → no `is_terminal` row → billing undercount; define terminal safety.
- No failover success/failure metric beyond the fail-open counter.
- Orphan `key_entitlements` rows for catalog-removed models.
- Whether the janus-auto **judge** call bypasses the deny pre-filter too.
- In-flight gun request cleanup on re-pick (only subscription cancel is mentioned).

## 5. Architecture notes
ETS rebuild atomicity is fine, but per-request reads need an explicit snapshot handle. Per-attempt rows + `WHERE is_terminal` is correct; fail-open rows must still mark terminal. Write ownership is clean (dashboard-only writer, gateway reader). Attempt accounting (`≤ max_attempts+2`) is internally consistent, but default budget 45s usually truncates the 4-call key budget to ~1 retry — knobs interact, document it. Knob delivery via persistent_term is consistent with invariants.

## 6. Top 5 edits
1. Set budget ceiling to `300s − TTFB` and fix the rationale.
2. Reconcile TTL ownership (delete A.1 "consumers enforce").
3. Exclude rate-limit 429 from key-scoped failover/cooldown.
4. Define terminal-row guarantees on crash/fail-open and the exhaustion error.
5. Re-probe rotated keys before honoring stale deny rows; drop duplicate test 16.
