# Audit — target.md (Key Entitlement Matrix + In-Request Failover)

## 1. Verdict
**GO WITH FIXES** — architecture is sound and failure-mode-driven, but the budget ceiling math is self-contradictory and the healing loop can't do what it claims.

## 2. Critical risks
- **Ceiling vs idle_timeout:** spec's own rule is worst-case wall = budget + one TTFB (60s), yet validates budget ≤ 280s "because < 300s Cowboy idle_timeout". 280+60=340s → bodiless 502, the exact failure the ceiling exists to prevent.
- **Balance starvation both ways:** (a) hourly healing tick vs 15-min balance window → only ~25% of balance rows ever get re-probed; (b) v1 traffic learning can't demote to `balance` (no error_code) and the healing loop only re-probes *existing* balance/deny rows — a key that drains mid-hour keeps `ok` rows forever; only cooldowns+failover mask it.
- **Retry storms:** up to 5 calls per client request (3 key retries + provider slot); a burst against a broken pool amplifies 5× before per-key cooldowns propagate. No pool-level breaker.
- **Probe cost/time:** 262 listings × (15s timeout + 1 retry) ≫ the 10-minute wall target; 1000-call cap has no defined truncation priority; call cap ≠ spend cap (2xx probes bill real tokens on premium models).
- **Streaming:** retrying collected error streams requires deferring status-line forwarding until classification — implied but unstated as an invariant.

## 3. Contradictions
- 280s ceiling vs budget+TTFB=340s>300s (above).
- Flow 11 and flow 16 are the same test (max_attempts=0), duplicated.
- Flow 17 vs pick rule: after all keys are `attempted`, even fail-open has zero candidates — the "reserved provider slot" has nothing to fire on.
- A.2 codes table "seeded from production evidence" vs E.4 "seeded from the classifier" — which is the source of truth?

## 4. Missing requirements
- Currency budget / wall-clock abort for probe batches; skip ordering when capped.
- Regex scope: apply only to error bodies (a 200 containing "未开通" must not classify).
- Stale matrix rows after listing renames (`model_name` has no FK to models) — orphan cleanup.
- `is_terminal` back-flagging rule when the deadline (not a response) terminates the loop; flow 12 assumes it, C.1 doesn't state it.
- Alerting on `janus_entitlement_failopen` and failover-rate spikes.

## 5. Design notes
- ETS snapshot-at-entry + generation swap is correct; keep deny-map read at loop entry, binary listing-name keys — as specced.
- `WHERE is_terminal` billing is right, but non-terminal 5xx attempts that consumed upstream tokens go unbilled — acceptable, document it.
- Dashboard-only writes / gateway reader via carrier: clean; missing-table tolerance good.
- 429 dual meaning: treating both classes as key-scoped-retryable gateway-side is correct.
- First-attempt-unconditional accounting avoids off-by-one; total ≤ max+2 checks out.

## 6. Top 5 edits
1. Validate `failover_max_budget_ms ≤ idle_timeout − TTFB` (~240s); fix the 280s justification.
2. Healing loop every 15 min (or window ≥ tick); add ok-keys-with-recent-429 to its probe set once E.1 lands.
3. Define provider-retry pick when `attempted` = pool (reuse coolest attempted key).
4. Probe budget: currency cap, wall-clock abort, cap-truncation priority; recompute 10-min feasibility.
5. Dedupe flows 11/16; state deadline-cut `is_terminal` rule; name the `entitlement_codes` seed artifact (SQL) as truth.
