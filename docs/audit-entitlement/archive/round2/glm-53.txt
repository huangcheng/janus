# Audit: target.md

## 1. Verdict
**GO WITH FIXES** — architecture is sound (dashboard-writes/gateway-reads respected, fail-open default correct), but one TTL contradiction starves balance keys and a few semantics are muddled.

## 2. Critical risks
- **Balance starvation (real bug):** A.1 gives balance a 1h TTL, but Part B's carrier ships both statuses with a 24h window — a topped-up key stays excluded ~23h beyond spec, and no scheduled re-probe exists (A.4 fires only on sync/new-key).
- **Classifier drift:** "ONE classifier, specced once" is implemented twice (Python probe + Erlang retry-side code-table copy). Divergence makes the gateway retry input-shape 400s as deny-shaped (wasted attempts) or skip real denies.
- **Key rotation:** spec says secret updates don't clear rows ("entitlement follows the account") — unenforced assumption; rotating to a *different account's* key inherits stale entitlements.
- **Budget overrun:** deadline is checked *before* each call; the last attempt can start at t=89.9s with 60s TTFB → ~150s total. Also 90s default exceeds the "typical 30–60s client budgets" the spec itself cites — clients abandon while attempts still burn.
- **Probe cost/shape:** 786-request batches; "halve in-flight for 30s" is meaningless for per-key *sequential* probing (in-flight=1). Chat-shaped probes against image/audio listings guarantee false `ok` (input_shape default) — accepted, but unstated cost.

## 3. Contradictions / stale claims
- Balance TTL (1h) vs carrier window (24h) — above.
- A.1 unknown paragraph is self-arguing garbage ("…indistinguishable-by-design is WRONG — no row = never seen") — rewrite.
- "Only the terminal row is counted" vs "`attempt = 1 OR terminal`": a 3-attempt request matches both rows 1 and 3 → double count.

## 4. Missing requirements
- Periodic probe cadence (e.g., daily deny-refill, hourly balance-refill) independent of model sync.
- Operator surface for `entitlement.key_broken` audits (dead keys otherwise invisible).
- Per-batch probe spend cap beyond JWT auth.

## 5. Architecture notes
- ETS generation-swap with entry-time snapshot is correct; deny-map keyed by listing binary matches the binary-vs-atom invariant. Good.
- Fail-open per loop-iteration correctly re-admits untried deny keys.
- 429 dual meaning handled acceptably at gateway (both retryable) since balance keys get matrix-excluded within an hour — *if* the TTL bug is fixed.
- Knobs via persistent_term distribution: consistent with repo invariant. Good.
- Streaming boundary (pre-first-byte error streams retryable, post-byte terminal) is correctly drawn.

## 6. Top 5 edits
1. Carrier SQL: `deny → 24h, balance → 1h` windows (or ship `checked_at`+status and apply per-status TTL gateway-side).
2. Add scheduled re-probe loop for expired deny/balance rows (A.4 extension).
3. Secret rotation → reset rows to `unknown`.
4. Single-source the deny code table (ship it in the catalog bundle; both sides consume).
5. Fix billing predicate: terminal-only for token counting, attempt=1-only for request volume; plus budget note documenting final-attempt overrun.
