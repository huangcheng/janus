**1. Verdict:** GO WITH FIXES — the fail-open deny default, snapshot reads, and bounded attempt budget are well-reasoned, but the B-carrier TTL bug, in-process probe lock, and traffic-blind balance loop will produce client-visible failures in production as written.

**2. Critical risks**
- Probe cost: the 786-row sweep has no spend cap or upstream-QPS circuit breaker; probes tripping provider rate limits self-poison the matrix (429 backoff mitigates, doesn't preempt).
- Deny classification: the hand-seeded per-provider code table drifts — one new provider wording is a blind spot, and unrecognized deny bodies fall into "non-deny 400 = terminal," so the motivating case still reaches the client.
- Latency: the budget gates starts only — a 60s-TTFB attempt begun at t=89 s ends ~150 s, and the 90 s default already exceeds the spec's own "typical 30–60 s client budget" (failover laboring for a departed client).
- Storms: constant 100–300 ms jitter keeps herds synchronized; zero-eligible fail-open dumps all concurrent requests onto the same cooling key at once.
- Balance starvation: 1 h TTL → `unknown` → real 429s, but A.3 forbids traffic demotion → oscillation until a probe re-marks; every oscillation is client-visible.
- Key rotation: in-place secret update keeps stale `ok` rows if the new secret belongs to a different account.
- Streaming: first-byte boundary is correct, but retryable drain depends on a parseable deny body (see deny risk).

**3. Contradictions / stale claims**
- A.1 lifetimes (deny 24 h, balance 1 h) vs B's single hard-coded `'24 hours'` carrier window for both statuses — balance rows ride excluded 24 h. TTL enforced in two places, disagreeing.
- `retry_provider` pseudocode omits `attempts_total < max_attempts`, contradicting "counts TOTAL calls incl. provider retry."
- "bounded by min(attempts×TTFB, budget)" is false arithmetic (budget is a start gate).
- A.1's "…indistinguishable-by-design is WRONG" sentence is garbled/self-contradictory.

**4. Missing requirements**
- Clock-skew tolerance in A.1 timestamp-guarded upserts (gateway event ts vs dashboard `now()`).
- Probe egress: proxy/TLS/egress parity with the gateway's upstream path.
- Metrics/alerts on `janus_entitlement_failopen` and failover rates.
- A.5 bind-time validation honoring row staleness/TTL.
- Cross-worker probe dedup (see risks).

**5. Architecture notes**
- Terminal-only billing under-counts upstream cost when a committed attempt later 5xx/timeouts; the 429 dual-meaning is resolved probe-side only.
- ETS binary-key snapshot per request is right; capture the deadline at entry, re-read PT knobs per attempt.

**6. Top 5 edits**
1. B: per-status TTL (balance 1 h / deny 24 h), or filter status in code; align the sqlite epoch window.
2. Probe single-flight via DB advisory lock (multi-worker safe).
3. Correct the bound to budget + in-flight TTFB; gate attempts on `min_remaining_budget`; reconcile the 90 s default vs client budgets.
4. Capture 429 balance-class at gateway track time (partial E.1) so traffic may demote balance, killing the oscillation.
5. Add ±clock-skew clamp to A.1's upsert comparison; fix the pseudocode guard and garbled sentence.
