## 1. Verdict
**GO WITH FIXES** — architecture (dashboard-owned matrix, read-only carrier, bounded failover) is sound, but the retry taxonomy is self-contradictory and the carrier SQL omits the `broken` status it claims to ship.

## 2. Critical risks
- **Probe blowback:** `JANUS_PROBE_MAX_CALLS` is defined two ways (A.2 per-batch vs A.4 per-provider daily), so pacing/budget enforcement is unbuildable as written. 429s share live rate pools.
- **Deny-regex FPs:** mitigated by fail-open default, but a genuine deny from an unlisted provider only fails over once — bounded, not eliminated.
- **Latency:** ceiling math (300−60−30−30=180) is right, but worst-case wall omits jitter×attempts.
- **Retry storms:** no pool-level breaker; per-request budget does not bound aggregate upstream calls.
- **Balance starvation:** canary model selection for key-scoped healing is unspecified.
- **Rotation staleness:** handled (delete-all + re-probe).
- **Streaming boundary:** handled (committed at first frame/reply).

## 3. Contradictions / stale claims
1. `JANUS_PROBE_MAX_CALLS` = per-batch hard stop (A.2) **and** per-provider daily budget (A.4), alongside a separate `JANUS_PROBE_DAILY_CALLS`.
2. B's carrier SQL selects `status IN ('deny','balance')` only, yet A.1/C.1 say the `__key__` `broken` row ships "with deny's TTL window" and C.1 skips known-broken keys from it. SQL never emits `broken`.
3. Input-shape 400: C.1 grants **ONE** failover attempt; test flow 8 asserts **NO retry**.
4. A.2 401/403 "leave prior rows untouched" vs writing a `__key__ broken` row.
5. A.2 429 "halve in-flight for 30s" vs "pause that provider's probe for 30s".
6. Provider-slot reuse ("coolest attempted key") vs the fail-open single-attempt flag — precedence undefined.

## 4. Missing requirements
- Aggregate/global upstream-call bound (retry-storm cap).
- Balance canary model choice; `broken` TTL value.
- `key_entitlements` retention (262 × keys rows grows unbounded).
- Idempotency handling beyond the 5xx note.
- Scope/auth detail for `POST /api/entitlements/refresh`.

## 5. Architecture notes
- **ETS atomicity:** dispatch-entry snapshot is correct; deny-map keys must be the exact binary listing name sent.
- **Usage rows:** `is_terminal` billing is sound, but legacy backfill and refresher counts must exclude non-terminal.
- **Write ownership:** dashboard-only writer + usage-event evidence is clean.
- **429 dual meaning:** single-source codes table good; empty-table fail-open defined.
- **Attempt accounting:** ≤1+max_attempts key calls + 1 provider slot; fail-open/reuse precedence unresolved.
- **Knobs:** persistent_term matches repo invariant.

## 6. Top 5 edits
1. Fix carrier SQL to include `status='broken'` (define its TTL) — or drop the shipping claim.
2. Collapse the two `JANUS_PROBE_MAX_CALLS` meanings into one.
3. Reconcile input-shape 400 behavior between C.1 and test 8.
4. Specify balance canary model + `broken` TTL.
5. Add an aggregate retry bound and matrix retention; define fail-open vs coolest-key-reuse precedence.
