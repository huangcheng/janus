**1. Verdict:** GO WITH FIXES — failure-mode-driven and internally coherent on the hard parts (TTLs, snapshot threading, billing), but the carrier SQL never ships `broken` rows and several knob/lock definitions contradict themselves.

**2. Critical risks**
- Probe cost/blowback: budgets, 150ms pacing, 30s provider pause suffice; probes sharing live rate pools is accepted-but-real.
- Deny false positives: fail-open default + field-scoped regex + 3-strike escalation is sound; residual risk sits in seed-table correctness.
- Latency: 180s ceiling math checks out; "default sits below common 30–60s client budgets" overclaims (45s > 30s).
- Retry storms: no pool-level breaker (acknowledged) — N concurrent requests on a dead pool = N×(max_attempts+2) upstream calls.
- Reload races: one generation snapshot threaded through all picks — correct.
- Balance starvation / rotation: 1h TTL + key-scoped canary + 25% reserved share; secret-update row purge — both addressed.
- Streaming: error-status collect_drain pre-byte retryable; 2xx-then-stall committed — boundary is precise.

**3. Contradictions / stale claims**
- **Carrier SQL (Part B) omits `status='broken'`** — WHERE lists only deny/balance, yet A.1 says `__key__` "ships in the carrier" and the catalog map includes `broken`. As written, broken keys never reach gateways.
- `JANUS_PROBE_MAX_CALLS`: "per-batch hard stop" (A.2) vs "per-provider DAILY budget" (A.4); daily is already `JANUS_PROBE_DAILY_CALLS`.
- A.2: "in-process lock" vs later "advisory lock is the single mechanism".
- Per-key sync probe "bounded ~2–4 min" contradicts 262×15s worst case and the 10-min batch cap.
- sqlite carrier SQL shipped, then declared Postgres-only/no-sqlite — dead text; "ship as gateway migrations? No —" is an editing artifact.
- E.5 "≤ (attempts+1) rows" vs C.1's max_attempts+2 calls (provider slot).
- RATE-class cooldown `max(Retry-After, 10s)` cannot "avoid benching a healthy key" — a large Retry-After benches it for hours; needs an upper clamp.

**4. Missing requirements**
- No healing path for `broken`/`__key__` rows — A.4 covers balance/deny/ok only; broken relies solely on 24h TTL expiry.
- No gateway-side validation when knobs come from sys.config (only settings-writes validated).
- Crash-backfill orphan detection underspecified — no query defined for finding request_refs lacking `is_terminal`.
- Test plan gaps: no rate-class 429 mock (dual-429 classification untested), no broken-key skip flow, no codes-table-empty gateway fail-open flow.

**5. Architecture/design notes**
- Deny map keyed `{ProviderId, ModelName}` with binary listing names + per-request snapshot: correct under the atomic-rebuild invariant.
- `is_terminal`-only billing + 300s grace crash-marking is coherent; 1s-buffer undercount accepted.
- Dashboard-writer/gateway-reader split (codes table via carrier, usage rows as evidence) respects the plane boundary.
- Knob delivery via persistent_term complies with the start-order invariant.

**6. Top 5 concrete edits**
1. Part B SQL: `status IN ('deny','broken') AND checked_at > now() - interval '24 hours'`; delete the sqlite variant.
2. Fix A.4: `JANUS_PROBE_DAILY_CALLS` is the daily budget; MAX_CALLS stays per-batch; drop "in-process lock".
3. Rate-class cooldown: clamp Retry-After to `[10s, 300s]`, not bare `max()`.
4. Add `broken` rows to the A.4 healing loop (~20h re-probe) or document expiry-only healing explicitly.
5. Test plan: add rate-class 429, broken-key-skip, and empty-codes fail-open flows; correct the 2–4 min per-key claim.
