## 1. Verdict
**GO WITH FIXES** — the design is coherent and boundary-clean, but A.1 and A.3/Part B contradict each other on who writes `source='traffic'` rows, and no §10 exists to pick a winner.

## 2. Critical risks
- **Mid-stream/SSE**: C.1's claim that the `Status >= 400` collect_drain path is retryable must hold for *all* translate modes (Responses→Messages, tool-call chunks). One emitted SSE byte locks in no-failover; the spec never states how the gateway proves zero client bytes before retrying.
- **Latency vs Cowboy**: worst case = 3 attempts × 60s TTFB = 180s against `idle_timeout=300_000`; slow-upstream retries can eat the entire handler budget.
- **Deny regex overlap**: the deny pattern includes `unsupported operation for this model`, which plausibly matches input-shape rejections — recreating the exact uni-api denylist bug A.2 claims to avoid.
- **Balance liveness**: `balance` rows exclude keys for 7d with no refresh mechanism in v1; a transient 429 silently shrinks pools for a week.
- **Probe storms**: A.4 auto-probes after every sync; N providers × missing coverage × 5 concurrency can self-inflict 429s against rate-limited keys.

## 3. Contradictions
- A.1: "`source='traffic'` rows are written by the gateway (Part C)" vs A.3: "A lightweight refresher **in the dashboard** … folds recent usage rows into the matrix" and Part B's header "(gateway, **read side**)". The gateway has no write path to `key_entitlements`; A.1 is stale.
- C.1: balance keys "fail over once, learn, and become deny-refreshable" — but neither A.2 nor A.3 defines any balance→deny refresh; balance rows only expire via TTL.

## 4. Missing requirements
- Terminal error contract on budget exhaustion (return last error? first? synthesized 502?) — unspecified.
- A.3 mapping: deny-from-traffic needs upstream *error text*; whether usage rows persist `error_code` is never stated.
- Probe single-flight mechanism (DB advisory lock? in-process?) undefined.
- E2E fixture only describes 401/200; items 1, 6, 7 need 404/429-balance/5xx/input-shape-400 mock modes.
- ETS rebuild race: deny-map swap vs in-flight picks unaddressed (likely benign, but say so).

## 5. Architecture notes
- Pre-filter ETS map with absence=eligible matches the LB cooling convention; process-dict attempt counter fits the per-request process model; dashboard-writes/gateway-reads respects the pure-gateway invariant. TEST-FLOWS (dashboard repo) must absorb flows 4–12.

## 6. Top 5 concrete edits
1. Fix A.1: traffic rows are written by the dashboard refresher only; delete "(Part C)".
2. Tighten the deny regex: drop `unsupported operation for this model` or require entitlement-keyword co-occurrence; add regex fixture cases to test item 1.
3. Define balance refresh: shorter TTL (e.g. 1h) or traffic-429-triggered re-probe.
4. Specify the exhaustion error contract and require `error_code` on usage rows for A.3.
5. Extend the mock upstream with 404/429-balance/5xx/input-shape modes so test items 1, 6, 7 are executable.
