**1. Verdict: GO WITH FIXES** — the headline failover goal contradicts its own retryable classification (and no §10 tiebreaker exists in the spec).

**2. Critical risks**
- Deny-shaped 400/404 is the production shape (DashScope "not activated", third-party family on 1 of 3 keys), yet C.1 retries only 401/403/429 — the motivating failure still reaches the client.
- Ownership clash: "dashboard-owned" table (A.1) vs a gateway boot-time `janus_db_conn` SELECT (Part B); if the dashboard migration lags, gateway boot fails. Carrier SQL is Postgres-only (`now()`/`interval`/`TIMESTAMPTZ`), breaking sqlite and the flat-migration convention.
- Retrying error-status streams rests on an asserted "existing `Status >= 400` collect_drain path" that is never named or verified.
- Generation bumps happen only on probe writes; traffic-learned denies never reach gateways.

**3. Contradictions / stale claims**
- "in-request key failover so a key-scoped upstream failure never reaches the client" (Goal) vs "NOT retryable: 400 non-key-scoped … return immediately" (C.1), given A.1 defines deny as "400 `not activated` / `no permission`, 404 `InvalidEndpointOrModel`". Nothing makes deny-shaped 400/404 retryable.
- A.1 "`source='traffic'` rows are written by the gateway (Part C)" vs A.3's dashboard refresher; C.1 writes usage rows only.
- C.2 "judge calls do NOT fail over" vs C.3 "do_proxy runs with the same failover loop" — suppression plumbing unspecified.
- A.1 balance "failing over once is acceptable" vs C.1 balance "excluded from picking entirely".

**4. Missing requirements**
- classify() must share A.2's deny regex so 400/404 key-scope is detectable; generic 400 stays terminal.
- A.3 maps no traffic 429 → `balance`; `checked_at` should carry event time (last-evidence-wins).
- Usage events must record `provider_key_id` + upstream error code/text — assumed, unverified against `janus_usage`.
- Migration owner/order, gateway tolerance of an absent table, sqlite carrier variant.
- `failover_max_attempts` delivery (settings → persistent_term) vs `janus_lb`'s existing attempt knobs.
- E2E: deny-shaped-400 failover fixture; TTL test with a manually back-dated row.

**5. Architecture notes**
- Retry loop must re-marshal translated bodies (Messages→Chat) per attempt; retain the parsed body, not an encoding.
- Cancel the prior gun subscription before re-picking; buffer client headers until first body byte.
- Deny + cooling pre-filter must skip excluded keys without burning attempt budget.
- Throttle generation bumps from traffic folds — deny churn causes catalog-rebuild storms.
- `deny_keys_by_model` keys must equal the model name actually sent upstream (listing name).

**6. Top 5 concrete edits**
1. C.1: classify deny-shaped 400/404 (A.2 regex) as `retry_key`; add the E2E case.
2. A.3: fold traffic 429 → `balance`; `checked_at` = event timestamp; bump generation on traffic writes.
3. A.1: delete "written by the gateway" — traffic rows come from the dashboard refresher.
4. Part B: pin migration ownership, boot tolerance, sqlite carrier variant, bump owner.
5. C.2/C.3: plumb an explicit no-failover flag for janus-auto judge calls through `dispatch/7`.
