**1. Verdict.** GO WITH FIXES — the core mechanics (per-request snapshot threading, single classifier, `is_terminal` billing) are sound, but attempt arithmetic, `input_shape` terminality, and probe-cost realism will bite in production.

**2. Critical risks**
- **Probe cost / rate blowback:** unclassifiable 400 → `ok+input_shape` → hourly re-probe until 3 escalations; unlisted modality listings (video/TTS variants) burn ~1 call/key/hour with no escalation path. "Never more than the provider's known RPM if lower" is prose, not a mechanism — 150ms spacing = 400 RPM.
- **Deny vs input_shape false positive:** `no permission`/`unsupported operation for this model` → `ok+input_shape` → C.1 treats known input_shape as TERMINAL zero-retries → deny reaches the client AND traffic can't heal it (A.3 ok-only until E.1). One classifier mistake permanently benches a key, client-visible.
- **Failover latency:** first call (TTFB 60 + body 30) is excluded from the ceiling formula (300−60−30−30=180); with pool_reuse + provider slots, worst wall approaches idle_timeout.
- **Retry storms:** N concurrent requests walk the same key sequence; cooling only helps after the first failure. No pool breaker (acknowledged).
- **Balance starvation:** warm reserve is per-provider; a provider whose day is eaten by bootstrap can starve entirely.

**3. Contradictions / stale claims**
- Attempt math: first + `failover_max_attempts` + reserved pool_reuse + reserved provider slot = **attempts+3 calls**, not "≤ attempts+2".
- A.2: broken heals "priority above balance"; A.4 list says "balance > deny > ok" — broken absent.
- 429 fail-open: "no cooldown" vs exhaustion contract "minimum 10s".
- A.3 traffic rows stamp the **gateway-written** event ts into a DB-arbitrated `checked_at` — clock skew unhandled.
- Part B undefined-table tolerance stated only for `key_entitlements`; "missing codes table is defined" needs the same explicit wrap.
- Advisory lock single-flight "per provider" also blocks the synchronous 2–4 min per-key probe — dashboard worker starvation risk.

**4. Missing requirements**
- Exhaustion path when no non-cooling candidate remains and fail-open already used (terminal error + counter).
- DAILY budget exhausted mid-queue: defer vs drop.
- Broken/balance counts in the key chip; probe-misclassification recovery when A.3 can only promote.
- Horizon: what re-admits an escalated row once E.1 lands (referenced, not specced).

**5. Architecture notes**
- Generation snapshot + ETS swap: sound; `(provider, model, listing-name-binary)` deny keying avoids collisions. Ensure failed attempts never carry token counts. E.1's `error_code` writes gateway-owned `usage_events`, not a management table — ownership invariant intact. 429 defaults to rate = retry — correct direction (worst case: healthy key benched 60s).

**6. Top 5 edits**
1. Fix call accounting to `1 + attempts + pool_reuse + provider = attempts+3`; reword knob semantics.
2. Split `input_shape`: premarked/structural → terminal; body-classified (`no permission`) → one bounded failover, then probe reclassification.
3. Replace the RPM prose with `interval = max(150ms, 60000/rpm)`, bounded by MAX_CALLS/wall clock.
4. `checked_at = LEAST(event_ts, NOW())`; wrap **both** carrier queries with undefined-table tolerance + assert in flow 3.
5. Resolve 429-cooldown and broken-key priority contradictions; define the all-cooling terminal path and budget-exhaustion deferral.
