# Spec Audit: Key Entitlement Matrix + In-Request Failover

## 1. Verdict
**GO WITH FIXES** — architecturally sound and unusually failure-mode-aware, but it contains three internal contradictions that would surface as production bugs if implemented literally.

## 2. Critical risks
- **Probe blowback**: well mitigated (pacing, dual budgets, reserved healing share, 429 pause). Residual: probes share live rate pools; the key-scoped balance canary never specifies *which model* it probes.
- **Regex FPs**: properly defused (anchored, code/message-scoped only, fail-open default, `input_shape` premark). Unlisted providers degrade to retry-once — bounded, acceptable.
- **Failover latency**: math holds (worst ≈ 273s < 300s idle_timeout); but only *error*-body collection is capped — slow 2xx non-stream bodies escape the ceiling formula.
- **Retry storms**: jitter + cooling + caps suffice; each client retry spawns a fresh loop (accepted, no pool breaker).
- **Reload races / balance starvation / rotation / streaming boundary**: all correctly handled (entry snapshot, healing priority, delete+bump, precise commit rule).

## 3. Contradictions / stale claims
1. **Codes-empty 429**: retryable-classes says "retryable, **no cooldown**"; exhaustion contract says "minimum **10s cooldown**". Direct conflict.
2. **All-broken pool**: A.1 says broken keys are *never* fail-open candidates and the request terminates; Part B/C.1's fail-open picks "any non-cooling, non-attempted key" — broken-marked keys not excluded.
3. **pool_reuse**: requires a "cooldown-EXPIRED, LRU" key, but default cooldowns (60s balance; max(Retry-After,10s)) exceed the 45s budget → the reserved provider slot can be silently unusable; test 16's "coolest key" wording differs.
4. Per-key sync probe "bounded ~2–4 min" vs 262 listings × (150ms + 15s timeout) — only the 10-min batch cap truly bounds it.
5. Leftover drafting artifact: "Both dialect variants ship as gateway migrations? No —".

## 4. Missing requirements
- Balance-canary probe model unspecified (a key whose rows are all balance has no obvious canary target).
- Crash-marking backfill has the *dashboard* writing `usage_events.is_terminal` — crosses the stated write-ownership boundary; needs an explicit grant.
- No alarm for chronic fail-open / all-deny providers (only the matrix-less alarm exists).
- Per-key synchronous probe holds an HTTP connection for minutes; client/proxy timeout behavior unstated.

## 5. Architecture notes
Snapshot-threading per request is the right shape; binary listing-name deny-map keys avoid the known bug class. `is_terminal`-only billing is correct with bounded undercount. Attempt math is consistent (≤ max_attempts+2). 429 dual-class via one codes table is the strongest design choice here.

## 6. Top 5 edits
1. Fix the codes-empty 429 rule: empty table → rate-class **with** max(Retry-After, 10s) cooldown.
2. Exclude broken-marked keys from fail-open picks in C.1; define the all-broken terminal error.
3. Define pool_reuse when no cooldown-expired key exists within budget (waive cooldown for the reserved 5xx slot); align test 16.
4. Correct the ~2–4 min sync-probe claim; state the 10-min cap applies and document caller timeout.
5. Grant the dashboard explicit `is_terminal` update rights on usage_events; specify the canary model.
