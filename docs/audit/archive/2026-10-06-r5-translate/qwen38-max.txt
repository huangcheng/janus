**1. Verdict:** GO WITH FIXES — five spec defects (error-path terminator semantics, usage-injection scope, unbounded accumulation, ping/non-content events, ship-unit e2e coverage) must be fixed in the plan text before 1.3 starts.

**2. Critical risks**
- **Error-path terminator contradiction:** C4 says “error event + terminator,” but C1 fixes terminators to success frames. For →responses/→anthropic the error frame *is* terminal; read literally, you emit `response.failed` **and** `response.completed` — a protocol violation strict SDKs reject.
- **include_usage injection scope:** C3 reuses injection but never scopes it. It must apply only to chat-protocol providers; sending `stream_options` to anthropic/responses upstreams is an unknown-field hazard.
- **Accumulation bounds incomplete:** 256KiB/call doesn’t bound call *count* or total bytes — many near-cap calls still blow `sse_st`. Also: completeness must be one JSON decode after full binary concat; per-fragment decodes or UTF-8 split across fragments fake truncation (exactly the fixture-realism bug class AGENTS.md warns about).
- **Lazy-emit trigger undefined for non-content events:** anthropic streams carry `event: ping`. If a ping triggers skeleton emission, the C4 failover window closes and a retry leaks client-visible bytes. kimi fixtures must contain pings.
- **Billing backward-compat:** unblock turns formerly-free 400s into billable attempts with usage rows; the knob is the only rollback — should ship **default off** and flip after the gate/smoke, not default on during a rolling deploy.
- Hot path is fine if completeness checks happen only at terminal signal; assert this in 3.4 soak.

**3. Contradictions / stale claims**
- prompt.md says E2E gate = 69 steps; AGENTS.md says 47. Cite `TEST-FLOWS.md`, never a count.
- 1.3 depends on 1.4–1.8 yet appears before them in checkbox order — confusing for agentic workers.
- C1 “terminator exactly once per COMMITTED response” contradicts C2’s error terminators (see §2).

**4. Missing first-ship requirements**
- 1.3 ship unit has no e2e assertions for 1.5 (`n>1` stream reject) or 1.6 (strip → `X-Janus-Dropped` non-stream / terminal-event stream).
- No error-type mapping table: anthropic `error` types (`overloaded_error`, `api_error`) → chat error JSON `type` → responses failure codes.
- Phase 2: synthesized id rules (`resp_`/`msg_`/`fc_`) and output-index allocation belong in 2.1, not improvised.
- Phase 3: nothing on `idle_timeout 300_000` compliance for the responses upstream adapter or per-attempt usage rows there.

**5. Architecture notes**
- One explicit mapping table per (source → target) family plus an unmappable-event policy (skip vs error); ping/unknown = skip.
- Error taxonomy as a first-class table: commit point (pre/post) × target × exact emitted frames × usage-row flag.
- Accumulator state needs total-bytes + distinct-call-id counters to enforce caps.

**6. Top 5 concrete edits**
1. Rewrite C4: error frame **replaces** the normal terminator (responses: `response.failed` alone; anthropic: `event: error` alone; chat: error JSON then `[DONE]`).
2. C3: scope include_usage injection to chat-protocol providers only.
3. C5: add per-stream caps (e.g., 64 calls / 1MiB total args) + single decode-at-close rule.
4. 1.0/1.4a: require kimi transcripts with `ping` events; define ping=skip in 1.1.
5. 1.3: knob default off, flipped post-smoke; add 1.5/1.6 e2e assertions and the billing-impact note to the ship unit.
