## 2. Critical risks
- **Usage-at-terminator vs chat skeleton.** OpenAI chat emits `finish_reason` chunk, then a usage-only chunk (empty `choices`), then `[DONE]`. C1's →chat skeleton omits the usage-only chunk, yet C3 says "emit usage at terminator." For chat→anthropic, `message_start` needs usage before any block but chat gives no early usage → you must emit null usage then real usage in `message_delta`, which contradicts "never invent token counts." Fix the skeleton and state the null-placeholder rule.
- **Anthropic `input_json_delta`.** `partial_json` fragments can split mid-JSON/mid-UTF8; they must be concatenated raw per `content_block.index`, never parsed per-fragment. C5 maps indexes but doesn't state this.
- **C4 "first translated frame" undefined.** For anthropic targets, `message_start` is synthesized immediately → retry window is zero. Define the window as "first upstream-derived content flushed," or defer synthesis until the first real upstream event.
- **Per-attempt state.** C4 resets `translate_sse`, but block-index maps, arg buffers, and synthesized ids must also reset. "Ids unstable across retries" is a client-visible regression absent from the error taxonomy.
- **Unblocking + entitlements.** Removing `has_tools`/`has_non_text_content`/responses gate (1.3, 2.3) unblocks traffic that today 400s. No per-route kill switch despite 2/7 auditors; default relies only on the global predicate.
- **Arg buffer bound.** 1MiB leftover cap is per-leftover; per-call tool args are unbounded → 3.4 soak can OOM.
