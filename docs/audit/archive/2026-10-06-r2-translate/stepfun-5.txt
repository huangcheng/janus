**Verdict: GO WITH FIXES** — a well-scoped plan that underestimates SSE-state complexity (four tool-index spaces, not one) and lacks a capture-harness task before its fixture promises, but its phase ordering and invariant contracts (C1–C6) are sound once fixed.

## Critical risks
- **C5 is underspecified.** You have *two* index spaces per direction (`content_block.index` counts text+tool+image; chat `tool_calls[i].index` counts tools only), and responses adds a third: output items (`message`/`function_call` items index globally, `function_call_arguments.delta` has *no* index at all — identity is positional per output item and per `item_id`). Anthropic→responses needs the item-index map; responses→anthropic needs a synthesized tool-index map. "Block-index↔tool-index map" doesn't cover the responses pair. Also name it in C4's per-attempt list.
- **C1 terminator claim is wrong for responses.** `response.created` is not a terminator guarantee — a pre-first-byte abort must still emit `response.created`+`response.completed` if the client stream has been created, or `response.failed`. Native passthrough behavior needs to be the reference, not the generic "translator emits `.completed`".
- **C3 omit `message_start` for chat.** Chat usage is the trailing chunk *only* under `include_usage`; the "reuse existing injection+retry" must be an explicit subtask, plus a false-usage guard on anthropic→chat when the upstream never sends `message_delta` usage.
- **C4 fails C5 under latency.** Translating before the first byte leaves argument buffers open pre-emit — define the pre-first-byte frame as the *first materialized event*, not the first TCP write, else tool calls are lost on failover.
- **1.6 is a policy change, not a passthrough.** Stripping `response_format` changes upstream contract for *native* request shapes too — the response header plus entitlement/LB interaction on retry after strip is unspecified.
- **1.7 unblocks types on the request path** — `input_json_delta` → chat `arguments` string trimming; images inside `tool_result` blocks have no chat equivalent, must be a documented reject (`tool_result_image_unsupported`), not a drop.
