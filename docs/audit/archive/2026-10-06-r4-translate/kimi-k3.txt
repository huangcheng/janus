**1. Verdict: GO WITH FIXES** — the skeleton/terminator contracts and phase ordering are now sound, but the C5 accumulation-bound claim is factually wrong and one header contradiction remains.

**2. Critical risks**
- **C5's "bounded by the existing 1MiB cap" is incorrect.** The SSE parser's leftover cap bounds a single unterminated *line*, not args accumulated across hundreds of `input_json_delta`/arguments.delta events. A hostile/buggy upstream streams unbounded tool args → per-attempt memory growth the plan claims is impossible. Add an explicit accumulated-args cap (e.g. 1MiB) with the C2 error path on overflow.
- **Header contradiction:** the impossibles table and 1.6 mandate `X-Janus-Dropped` headers for stripped `cache_control`/`response_format`, but C2 declares stream headers carry no degradation info. Request-time strips are known *before* commit and could lawfully go in stream headers; qualify which degradations are header-eligible (pre-commit-known) vs terminal-event-only (mid-stream-discovered).
- **Multi-turn reasoning round-trip unaddressed:** anthropic requires thinking blocks echoed back with tool_use turns; chat→anthropic drops them, responses reasoning items are id-keyed server state. Cross-protocol continuation after a tool turn will break or silently lose reasoning. Document as impossible or persist-replay; silence here ships a bug.
- Failover/entitlement: nothing states translated streams can't double-count usage when a pre-commit retry hits a second upstream — "per-attempt rows" exists but no assertion that exactly one row is billable per client-visible attempt.
