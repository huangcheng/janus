**Critical risks**

1. **Pre-accept failover self-contradicts.** R5 header pins SAME-MODE; A5 body allows cross-mode. Async/sync wires are structurally different — cross-mode cannot dispatch. Pin SAME-MODE in both places. (The rev-6 summary itself contradicts: "pre-accept failover pinned SAME-MODE" vs "pre-accept failover may cross modes" inside the same paragraph.)

2. **`video_jobs` phase gap.** M1.1 row model references `video_jobs.status` transitions; M3.3 creates the table. Move the migration to M1.1 or make the writer conditional — plan does neither.

3. **Lazy emission vs heartbeats.** "Nothing until upstream ACCEPT" + "synthesized ≥1/10s events" — heartbeats ARE writes. Pre-accept can run the full 270s budget. Heartbeat emission must start at request entry.

4. **Status vocabulary mismatch.** R5 header: 3 values; M1.1: 5 + NULL (cancelled, abandoned video-only). State the superset explicitly so writer enum and `video_jobs.status` agree.

5. **`first_media_byte` undefined on synthesized-only sync holds.** No upstream byte ⇒ redefine as "first byte this gateway emits" so `commit_point` is well-defined.

6. **Usage idempotency without UNIQUE jvid index.** Crash between `video_jobs.status` transition and usage INSERT duplicates on next poll. Specify CAS-on-transition (UPDATE…RETURNING or affected-rows check).

7. **TTS post-accept pre-first-byte path.** "JSON error" + "no mid-stream error" + "no post-accept failover" — three rules collide. Specify: pre-headers, one JSON error, no failover; post-first-byte, truncate.

8. **jvid retention "until retention > max exp"** has no mechanism. Add `jvid_retention_hours` knob (≥ `jvid_ttl_hours`).

**Contradictions vs codebase.** Pre-accept mode header/body split (and internal rev-6 split); "vocabulary unified" vs six-value column; rev-6 claim "video wire contradiction resolved ONCE" is false (item 1 unresolved).
