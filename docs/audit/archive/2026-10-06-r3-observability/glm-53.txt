# Audit — Janus Observability Plan (rev 3)

## 1. Verdict
**GO WITH FIXES** — rev 3 resolves all round-2 findings correctly; what remains are step-level ambiguities and stale text, not architecture.

## 2. Critical risks
- **Cardinality:** closed enums + operator provider names only; `lb_stat{counter}` bounded by `janus_lb:stats/0` keys. Sound.
- **Hot-path cost:** ~16 `ets:update_counter` + `ets:whereis` per request, ns-scale, whole-body try/catch. Sound.
- **Exposition:** registry-driven families, one HELP/TYPE, cumulative zero-filled buckets ascending with `+Inf` last, correct escape order (backslash before quote/newline). Sound; `le` appended unsorted is cosmetic.
- **Auth reuse:** verbatim extraction + delegate; peer-IP loopback, never XFF. Sound.
- **Bucket sanity:** `observe` bumps every bound ≥ value (cumulative); renderer shares the same canonical ladder — no drift possible.
- **Request-id hygiene:** `[A-Za-z0-9-_]{1,128}` blocks header injection; generated ids lowercase; echo verified on 401/stream.
- **Migration/dialects:** ledger-deduped `ADD COLUMN` + `IF NOT EXISTS` index, identical SQL, `null`-atom binding precedent. Sound.
- **Multi-node:** per-node jobs/tokens; never-sum-LB-gauges note. Sound.

## 5. Architecture/design notes
`ets:update_counter/4` with a default tuple is race-free create-and-bump; whereis-per-bump trades one hash lookup for restart safety — right call. Renderer purity justifies the eunit-first fixtures. Single terminal hook at `track/3` is correct; inner failover attempts can't double-count. `set_resp_header` at handler entry on the one Req chain covers `stream_reply` — verified by construction plus gate asserts. Note: families sort **within type group** (counters→histograms→gauges), not globally as the docblock implies — harmless, fix the wording.
