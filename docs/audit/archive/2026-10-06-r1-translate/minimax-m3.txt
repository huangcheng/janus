**1. Verdict:** GO WITH FIXES — phase ordering is sound, but terminator/usage semantics, tool-call ID stability under failover, structured output, and reasoning mapping are all silent, and the conformance-fixture plan will rot without an explicit refresh contract.

**2. Critical risks**

- **Terminator/usage semantics per direction.** When translating chat→anthropic with tools, `finish_reason=tool_calls` plus anthropic `message_delta.usage` must reach the client in correct order, and `data:[DONE]` must be the literal last byte. Plan enumerates none of this for the 6 streaming pairs.
- **Tool-call ID stability under failover.** Per-attempt `sse_st` restart on retry means the next attempt emits fresh `call_xxx` ids for the same logical call; chat clients see inconsistent state across a retry. Plan silent.
- **Vision in OUTPUT.** "Extend STREAM reply side" for image parts assumes a standardized vision-OUTPUT shape — it doesn't exist (chat `image_url` in content, anthropic image blocks, responses `output_image`). Either drop the claim or commit a per-pair behavior matrix.
- **Predicate unblock is a visible behavior change.** Removing `has_tools/has_non_text_content` from `stream_translate_blocked` silently enables previously-400'd requests; E.5/E.6 gate expectations must be updated in the same commit and clients need a migration note.
- **Structured output and reasoning are in the goal but absent from the phases.** `response_format` ↔ `text.format` ↔ anthropic tool-forcing, plus anthropic `thinking` ↔ responses `reasoning` items ↔ chat drop-with-header are not mapped.
- **Conformance fixtures rot.** "Real captured SSE" per provider family (dashscope/volcengine/kimi) becomes stale on every upstream SDK release; no refresh mechanism proposed.
- **Phase 2.2 hidden assumption.** "Non-stream versions exist" for responses→chat/anthropic — verify or expand scope.

Sibling-repo gate has 69 steps (AGENTS.md); E.5/E.6 implies a smaller subset — either outdated naming or a different gate than the audit column's mental model. Goal lists "structured output"; no phase task covers it.

**5. Architecture notes**

`sse_st` gains `pending_tool_calls` (chat↔anthropic) and `pending_output_items` (responses). `translate_sse` dispatch needs a `responses_target` variant decoupled from current direction-pair modules (events are response-object-shaped, not delta-shaped). Error taxonomy: `n_unsupported`, `translate_failed`, `malformed_tool_args`, `unsupported_image_format`, `reasoning_dropped`. Per-direction event-mapping tables (6 streaming pairs) belong in `apps/janus_http/src/janus_protocol_translate.erl` as comments/`@doc` or a sibling `docs/protocols/translation.md`, and are prerequisites for the 1.4 / 2.4 / 3.2 E2E steps.
