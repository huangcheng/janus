# Audit: Janus next-phase design spec

**1. Verdict:** GO WITH FIXES — the four slices are correctly scoped and dual-repo pairing is right, but counter double-counting, a vacuous deploy generation check, and unmapped provider `error` events must be fixed before implementation.

**2. Critical risks**

- **Counter invariant breakable.** Slice B: `track(400)` fires for mid-stream `translate_unsupported`, then if the handler later crashes, the `after` path adds **another** `inc_failed()` — failed can reach 2× total, violating `failed <= total`. The `janus_stats_counted` flag guards total, not failed.
- **Deploy wait is vacuous on code-only deploys.** Gateways poll DB for generation; if the ship includes no dashboard config write, leader and followers already agree, and the 300s/two-consecutive-poll check proves nothing about the new release. Slice D never mandates a generation bump.
- **Provider-sent `error` events unmapped.** §4.1.3 defers Anthropic `error` to §4.1.4, but §4.1.4 only covers `translate_unsupported` and drain failure. `overloaded_error` / `api_error` mid-stream (and OpenAI's in-stream error chunk) have no defined client frame or track status.
- **Disconnect semantics underspecified.** "Cancel gun" is stated, but not whether a usage row is written (partial tokens? status 502 via track?) or whether `janus_usage_head` finalize still runs.
- **Unbounded `leftover`.** `sse_events/2` buffers an incomplete tail with no size cap; a hostile/buggy upstream emitting a never-terminated `data:` line grows handler memory indefinitely.

**3. Contradictions / stale claims**

- §4.1.3 says Anthropic→Chat usage rides on the `message_delta` chunk ("emit a separate empty-choices chunk with usage"), but OpenAI native order is finish-chunk → usage-chunk → `[DONE]`; the spec must pin ordering or Chat clients reading `finish_reason` then closing miss usage.
- AGENTS.md is quoted as both wrong (`--target build`) and authoritative elsewhere; fine, but Slice C must land before Slice A eunit per §9 — confirm the paired-PR rule doesn't block C (C has no dashboard leg; that's consistent, just state it).

**4. Missing requirements**

- Chat→Anthropic: first chunk often carries `delta.role` with no content — emitting `content_block_start` immediately is fine, but specify behavior if the stream ends with zero content (empty text block before `message_stop` is illegal for strict Anthropic SDKs).
- Multi-block interleave (text → thinking → text) on the Chat face: state only tracks one open block; define second-text-block behavior.
- Unsigned `thinking` blocks break multi-turn follow-ups on Anthropic clients — "document" is named but no doc target (SPEC.md? README?) is assigned.
- No fixture shape specified for TF-6.8/6.8b assertions (byte-grep on raw SSE vs parsed events?).

**5. Architecture notes**

- Handler-owned `#sse_st{}` + PT-held atomics matches existing `janus_usage` precedent — good. Do not let `translate_sse` live in the drain callback process if gun messages are re-routed; pin the owner explicitly.
- Native-path byte-identity invariant is correctly preserved.

**6. Top 5 concrete edits**

1. Make failed-at-most-once: `track/3` sets `janus_stats_failed` flag; `after` path checks it before `inc_failed()`.
2. Slice D: require dashboard to bump generation as a deploy step; success = generation **> pre-deploy value** and stable twice.
3. Add provider `error`-event rows to §4.1.3/§4.1.4 with explicit frames + track status (502).
4. Pin Chat-face frame order: finish chunk → empty-choices usage chunk → `[DONE]`; state disconnect usage-row semantics.
5. Add `leftover` size cap (e.g. 1 MiB → error frame + terminate) and assign the unsigned-thinking documentation target.
