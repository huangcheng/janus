**1. Verdict:** GO WITH FIXES — rev 5 resolves all round-4 findings credibly, but one claimed fix (avg null-on-empty) is not actually in the code, plus a handful of small defects remain.

**2. Critical risks**
- **SSE fidelity:** Max-per-field merge is correct for cumulative dialects; genuine-zero now survives symmetrically. Regex fallback only fires when *zero* lines decode — a partially-decodable tail (one good non-usage line + truncated usage event) silently returns `undefined` instead of falling back. Low probability, real gap.
- **Dual-DB SQL:** `DELETE … LIMIT` in subquery is valid both dialects; `percentile_disc`, `strftime`/`to_char` parity OK. `bucket_expr` Postgres day label hardcodes `T00:00` — matches SPA slicing, fine.
- **p95 cost (SQLite):** `ORDER BY latency_ms LIMIT 1 OFFSET ?` sorts the whole window per summary call, every 30s poll, over up to 31 days of rows. No index on `(stream, latency_ms)`. This is the heaviest recurring query in the plan.
- **Buffer failure modes:** `whereis(undefined)` in `guarded_cast` drops events **uncounted** — writer-down is visible via `writer.alive` but the loss is invisible in `dropped`. `terminate/2` flush of a full 10k buffer = 200 sequential INSERTs; exceeding the 15s shutdown kills the rest silently (no count, no log).
- **`maybe_trim` chunk-cap branch:** keeps stale `Size` after dropping chunks (byte count no longer matches kept chunks) — correctness survives via the refold, but the invariant is broken and the test ignores it.
- **Migration/identity:** FK type-check and PRAGMA checks are properly deferred to Step 3; SET NULL-inert fallback documented. Sound.
