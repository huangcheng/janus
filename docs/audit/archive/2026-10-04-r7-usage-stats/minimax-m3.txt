**Verdict: NO-GO** — two hard defects (compile error, failing test) plus an avg-on-empty regression that contradicts rev 4.

**Critical risks**
- **Compile error, Task 3**: `_ = proc_lib:spawn(fun sweep/0)` — `proc_lib` exports `spawn_link/1`/`spawn_opt/2`/etc., never `spawn/1`. Module will not compile. Use `erlang:spawn/1`.
- **Trim-tail test fails, Task 6**: `maybe_trim/2` over-cap branch ends in `lists:reverse(Kept)`, but the fold accumulates newest-first in iteration order, so reversing yields oldest-first. `trim_keeps_newest_within_byte_cap_test` expects `{[C3,C2],16384}` from `[C3,C2,C1]`; implementation returns `{[C2,C3],16384}`. Drop the reverse.
- **avg null-on-empty regression, Task 4**: `COALESCE(AVG(CASE WHEN stream=0 THEN latency_ms END),0)` forces 0 on empty/non-matching sets, then `round(num(0))=0`. Plan claims null-on-empty (rev 4) and SPA renders `?? "—"`. Result: empty windows show "0 ms" while `p95_*` shows "—". Drop the COALESCE on the AVGs and route through `num_or_null/1`.
- **SSE fidelity for openai_responses**: `maybe_inject_stream_usage` only handles `openai_chat`. Native-path Responses streams get no `include_usage` injection; tail-capture is the only fallback and regularly misses `response.completed` even with the regex fallback. Inject for `openai_responses` or document explicitly.
- **p95 cost**: SQLite p95 issues `SELECT COUNT(*)` then `SELECT ... LIMIT 1 OFFSET N` per call. For 30-day windows with hundreds of thousands of rows this is O(N) twice. Add a covering index hint or cache.
