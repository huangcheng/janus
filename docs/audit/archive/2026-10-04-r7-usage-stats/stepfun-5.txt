**1. Verdict:** GO WITH FIXES — one hot-path data-loss defect, one log-flood defect, and several stale/under-enforced claims must be edited; the core design is sound.

**2. Critical risks**
- **Disconnect loses the row (worst):** T6's success branch runs `ok = cowboy_req:stream_body(<<>>, fin, Req2)` *before* `track`. A closed client makes that call exit/badmatch → request process dies, tokens burned, no row, no 502 record. Also, "Drain surfaces callback exceptions as `{error,_}`" is asserted, never verified — if `_ = stream_body(..., nofin, ...)` raises inside the callback and Drain doesn't catch it, the same crash occurs. Hoist `note_*`/`track` above the fin call (or try-wrap the block) and grep Drain's actual callback error contract.
- **Log flood:** the mailbox-full path in `guarded_cast` emits `logger:warning` per dropped event. Throttling was added only to the gen_server paths; a DB stall under traffic becomes a per-request log write. Count silently via atomics, log every Nth.
- **Writer-down silent loss:** `whereis(?SERVER) =:= undefined` drops with `ok`, uncounted — contradicts the "never silently lost" contract.
- Dialect SQL checks out: nearest-rank p95 ≡ `percentile_disc`, `LIMIT`-in-subquery delete valid on both, bucket labels byte-identical, `?`→`$N` rewrite sound. Migration/retention consistent (31>30; `ts` index keeps sweep COUNT cheap); the PG parent-id precheck is a genuine step. Sweep cap logs when hit — adequate.
