## 1. Verdict

**GO** — I found no unresolved sentence-pair contradiction; the remaining issues are implementation-contract hardening rather than design blockers.

## 2. Critical risks

- `#sse_st{}` lacks the `usage_sent` / `finish_sent` fields that later prose requires, making duplicate/missing usage and finish frames likely.
- Parser behavior is underdefined for malformed JSON, multiline SSE `data:` lines, unknown Anthropic events, and `message_delta.stop_reason=null`.
- After headers are sent, finalization and `gun:cancel` must be exactly-once; otherwise clients can receive duplicate terminators or upstream connections can leak.
- Cowboy’s 300-second timeout is inactivity-based: a silent provider without pings will still terminate long-running streams.
- Counters reset on application restart while remaining monotonic between reloads; the dashboard must correlate them with `started_at` and distinguish tracked status from wire status.
- The named `_build` volume can retain incompatible beams if OTP, compile options, or dependencies change without the documented wipe.
- Follower acceptance of **any** generation `> gen0` can pass on an unrelated concurrent configuration change rather than the shipped generation.

## 3. Contradictions or stale claims

No direct blocking contradiction found. The stale/incomplete item is the `#sse_st{}` definition versus later references to `usage_sent` and `finish_sent`. Claims about the existing Dockerfile mirror, `.dockerignore`, and SPA optional fields should be verified while implementing.

## 4. Missing requirements

- Exact malformed-JSON contract: skip raw event, return parser error, or pass binary data to `translate_sse`.
- Whether multiline `data:` is unsupported or must be concatenated per SSE rules.
- Policies for unknown provider event types, out-of-order block indices, and null stop reasons.
- Exact sanitized error JSON schema, truncation behavior, and golden wire examples.
- Whether synthesized zero token counts are display-only or may enter the usage row.
- Scoped clearing of `janus_stats_inner`; otherwise a retained process-dictionary flag can suppress the outer failure count.

## 5. Architecture/design notes

The single Cowboy handler owning SSE state, immediate drain writes, and sole finalization path are sound. Atomics initialized before listeners avoid listener/start-order races. Inner janus-auto counting needs explicit process-dictionary scope management. The paired dashboard PR requirement is necessary because API, SPA, SPEC, and TEST-FLOWS changes are inseparable.

## 6. Top 5 concrete edits

1. Add `finish_sent` and `usage_sent` to `#sse_st{}` and define every transition.
2. Specify malformed JSON, multiline `data:`, null stop reasons, and unknown-event handling.
3. Wrap inner janus-auto calls in scoped flag setup/erase with `try/after`.
4. Require follower generation to equal the captured leader generation on two polls, or explicitly document why unrelated newer generations are acceptable.
5. Stamp or name the `_build` volume with OTP plus `rebar.lock` fingerprints to prevent silent ABI reuse.
