**1. Verdict:** GO WITH FIXES — rev-10 folds are present and coherent; remaining gaps are bounded hygiene (stale fields, one missing clamp, first_seen sweep, execution-order omission), none architectural.

**2. Critical risks (new parts):**
- *cache_put `first_seen` unbounded:* the per-sender entry cap (4 096) bounds live rows, but `first_seen` records for expired hashes are never swept — a churning peer leaks memory. Tie `first_seen` expiry to `first_seen + 2×TTL` and reap it in the 30 s sweeper.
- *`Target` is not byte-clamped:* ingress clamps `AgentKeyId` (≤128 B) and `Hash` (64-hex) but not `Target` in `lb_cool`/`lb_lat`/`lb_recovered`/`lb_cool_purge`. A compromised peer can push oversized binaries into ETS. F.3 residual-trust softens this (cert-holders already own arbitrary-exec), but defense-in-depth is the spec's own frame — clamp it.
- *Quota 2 s cadence:* top-32 + ≥50 % filter + upsert-per-(sender,key,window) bounds load; advisory-only ⇒ zero pick-path exposure. Sound.
- *erpc enum:* registry + `function_exported` precheck + local arg validation closes the HTTP surface; `undef`/`timeout`/`noconnection` classes correctly mapped and eunit-driven. Note: the precheck is LOCAL, so the issuing node must be current during rolling deploys.
- *Lease:* lowest-node-name is deterministic; dual-hold window ≤ net_ticktime+5 s; v1 duty is observability-only ⇒ blast radius ~0. Sound.
