## 1. Verdict
**GO WITH FIXES** — architecture is sound and prior rounds are genuinely resolved, but Task 7's filter code is broken as written and two claimed safeguards are illusory.

## 2. Critical risks
- **Task 7 `handle_usage_events`**: `maps:filter/2` predicate must return `boolean()`; it returns `{true, {key_id, N}}` → badarg/500 (or all filters dropped). Even as `filtermap`, the map keys stay `<<"key_id">>` while `recent_filters/1` pattern-matches `{key_id, V}` (atom) → filters silently ignored. Breaks the "filtered drill-down" requirement.
- **Sweep SQL as written**: `LIMIT ?BATCH` goes through `rewrite_pg` → `$NBATCH` (or `?BATCH` unbound on SQLite). The note says "inline 5000" but the copyable code is wrong.
- **`no_qmark_literals_test` is a no-op** — it reads a `file` attribute and asserts `length > 0`; it never scans SQL. The "`?` literal is enforced by eunit" claim is false.
- **Read path not exception-safe**: `{ok, Rows} = q(...)` badmatches on DB error → dashboard endpoint 500 (writer is safe, reader isn't).
- Tail capture copies ≤16KB per chunk; head/tail overlap (4–20KB streams) double-decodes events — safe only because `lists:max` is idempotent; delta emitters would inflate both axes.
- Per-event `logger:warning` at cap = log flood under a stalled DB. `avg_latency_ms` still mixes stream/non-stream (and is exported but never rendered).
- Postgres lane (`percentile_disc`, `to_char`, SMALLINT binds) is verification-optional → effectively untested.

## 5. Architecture notes
Buffered writer design (drop-newest cap, 50-row atomic chunks, trap_exit flush, unlinked sweep worker) is right; note `shutdown 5000` vs slow terminate flush. pdict erase-at-entry correctly handles cowboy keep-alive reuse. Parser is pure/total; `{0,0} → undefined` conflates genuine zero with absent. Rollup SQL is dialect-correct: `ceil(0.95N)-1` == `percentile_disc(0.95)`, bucket exprs are UTC on both, `||`/`CAST AS TEXT` valid in both.

1. Rewrite `handle_usage_events` with `maps:filtermap` emitting `#{key_id => N}` / `#{model_id => N}` matching `recent_filters`, or match binary keys there.
