**2. Critical risks**
- **Inflight-hint staleness regression:** after B.1 nothing reaches the pool at reserve time, so snapshot `inflight` refreshes only on completion casts or the 30 s tick. Under sustained long streams without completions, knobs-off v1 least-inflight balancing silently degrades — a selection-semantics change on the production default path. Fix: pick reads `sched_reserve` live (public, `read_concurrency`) for the inflight component; snapshot stays for health/rtt/geo. Otherwise document the staleness as accepted.
- **13.7 "<30 s nodedown"** holds only if docker-kill's TCP RST propagates; at default `net_ticktime` 60 s, silent-death detection is 60–75 s. Pin the RST assumption and/or run the gate with `JANUS_NET_TICKTIME=30`.
- **Purge ownership unpinned:** "reaps ALL expired rows" must be per-key `ets:take` like release/nodedown; delete-then-decrement racing a concurrent release double-decrements (clamp heals, but the pin is what the "post-purge done no-op" eunit actually proves).

**5. Architecture/design notes**

- `ets:take`-owned decrement is the correct idempotence spine — keep it uniform across release/nodedown/purge.
