## 1. Verdict
**GO WITH FIXES** — the rev-4 remediation is mostly real, but Task 4's test module cannot compile as written, and two rev-4 claims (genuine-zero on SSE, hot-path safety) are not actually delivered.

## 2. Critical risks
- **SSE fidelity**: `from_sse` still returns `undefined` when `{P,C} =:= {0,0}`, so a genuine-zero stream collapses to *unreported* — the exact round-3 bug. `from_response_body` was fixed; the SSE aggregate was not, and no test covers it. Track "any decoded usage found" as a boolean instead.
- **Hot path**: `ok = cowboy_req:stream_body(Chunk, nofin, Req2)` (Task 6 Step 2) badmatches on client disconnect — a *common* case. Process crashes, no row recorded, drain aborted. Use `_ =` and record a terminal status.
- **Hot path 2**: `drop_counter/0` calls `persistent_term:put/2` from a cowboy request process — that is a global lock + all-processes heap scan. Create the atomics ref in `init/1`.
- **Injection**: `maybe_inject_stream_usage` re-encodes the body but the claim "the adapter sets its own Content-Length" is unverified. If any adapter sends `Body2` with the original header, **every OpenAI stream breaks**. Verify before default-on.
- **Identity/FK**: `recent/2` and `breakdown_dim/1` assume `api_keys.prefix`, `models.name`, `providers.name`, `provider_keys.provider_id`. Task 1 Step 3 checks table *existence* only. Add `PRAGMA table_info` checks.
- **Dual-DB**: `totals/2` destructures a 7-tuple outside any `try` — a driver shape difference is a badmatch→500, the round-3 class. `num/1` may silently yield `avg_latency_ms => 0` if epgsql returns numeric as a tuple/decimal. Postgres lane is "optional", so this ships unverified.
- **Sweep**: 100×5000-row DELETEs compete with flushes for SQLite's single write lock; no `busy_timeout`, no post-sweep `VACUUM`. Flush-error logs are unthrottled (200 chunks/sec if the table is missing).

## 5. Architecture notes
Buffered writer shape is right (drop-newest, trap_exit, counted losses), but `chunk/2` recomputes `length/1` per recursion — O(n²) at 10k rows, ironically reintroducing what rev 3 fixed in the tail. `rewrite_pg/2` is byte-recursive O(n²) binary building, uncached, per query. A summary poll issues ~8 serialized queries through `janus_db_conn`, contending with flushes; p95-on-SQLite costs 4 of them. Consider computing p95 in the same scan or caching the summary briefly. Tail capture (`trim_tail` newest-first, `iolist_to_binary`) is chronologically correct — good. `from_sse` maxing across events correctly handles Anthropic's split input/output, and the regex fallback for oversized `response.completed` is sound; note it scans up to 20KB per usage-less stream. Stream `latency_ms` measures client drain, so p95-stream reflects client bandwidth more than provider speed — the SPA subtitle should say so.
