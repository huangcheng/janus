**Verdict:** GO WITH FIXES — every round-4 fold is present and coherent; three small precision gaps.

**Critical risks**
1. **B.1 write-order failure mode unnamed.** The pinned counter increment is badarg-IMPOSSIBLE, but the subsequent `ets:insert(sched_tracked, …)` can independently throw (table not heir'd yet at boot, `badarg` on race with adopt, system_limit). Reserve excess then needs heal via the two-tick reconcile — the release's take-not-found is the same path, but the spec never names the insert-failure → reconcile-heal guarantee. Add it next to "take() owns the decrement."
2. **C.4 dirty-tree overreach.** `git status --porcelain` empty-required will fail on the operator's temp `.env`/local notes that should not block prod deploy. Whitelist (`.deploy-allowlist`) or document `--allow-untracked-known` for emergencies.
3. **13.8 fail-fast bound fragility.** The 15 s relies on docker SIGTERM's 10 s grace closing sockets cleanly. A hanging shutdown (e.g., DB pool drain) can blow the bound. Either widen to < 20 s with a SIGKILL fallback assertion, or assert per-event (socket close observed via process-monitor, not wall clock).

**Contradictions or stale claims**
- "Workers view field set deliberately MATCHES the production view field-by-field" — the prod view's field names should be quoted verbatim from the eval report, not paraphrased, or the deploy-neutral promise is uncheckable.
- 13.7 `dispatch_worker{w2,_}` delta ≥ 1 assumes survivor has capacity 0/1; with `JANUS_WORKER_CAPACITY=32` the first request is fine but the spec should pin the gate's worker capacity (recommend 1) so affinity+capacity interacts deterministically.
- Part E "Pre-byte predicate" reads "no chunk forwarded AND no done/error emitted" — bytes buffered at the worker but not yet forwarded are also pre-byte (the documented double-billing risk), state it explicitly.
