## 1. Verdict
**GO WITH FIXES** — the spec is tight and §10 closes prior rounds, but a few *new* concrete defects remain: the Slice C documented command references `./rebar3` while the repo root is explicitly not mounted, `finalize_sse(normal)` frame composition is unspecified, and the post-200 error taxonomy (400 vs 502) is internally ambiguous.

## 2. Critical risks
- **Slice C command bug**: `docker run … sh -c './rebar3 …'` mounts only `apps/ config/ rebar.config rebar.lock`; `/app/rebar3` exists only if the image COPYs it there. Spec says `COPY rebar3 /usr/local/bin/rebar3` — so `./rebar3` fails. Either invoke `rebar3` (PATH) or COPY to `/app/rebar3`.
- **finalize_sse(normal) undefined**: drain EOF with `terminal_sent=false` must emit pending finish chunk + pending usage chunk + terminator from stashed state, with defaults when no stop_reason/tokens seen. Spec defines only "exactly one terminal".
- **Error taxonomy collision**: `translate_sse` returns `{error, translate_unsupported}` for provider-origin tools (→502 per §4.1.2), yet §4.1.4 row 1 maps "client-origin translate_unsupported after 200" → 400. Client-origin cases are already rejected pre-200 (§4.1.1); the only post-200 400 is response `n>1`. The handler cannot distinguish origin from the error tuple.
- **rebar3_fmt plugin**: `fmt --check` may fetch the plugin from hex at runtime if not pre-fetched in the image's compile step.

## 3. Contradictions / stale claims
- §4.3 `./rebar3` vs `/usr/local/bin/rebar3` (above).
- §4.1.4 row 1 vs §4.1.1: "client-origin translate_unsupported after 200" should be unreachable except mid-stream `n>1`; rename the cause.
- `role_sent` in `#sse_st{}` is never referenced by the mapping tables; either use it (synthesize role chunk if provider omits `message_start`) or drop the field.

## 4. Missing requirements
- Anthropic→Chat: `content_block_start` carrying **non-empty initial text** is silently dropped — specify emit-as-first-delta or log+drop.
- `sse_events` must state it skips SSE comment lines (`: …`) and handles multiple events per chunk on **both** faces.
- Counter edge: janus-auto judge `track(200)` sets `janus_stats_tracked`; state explicitly a later target 4xx still bumps failed once (gated by `janus_stats_failed`, not `tracked`), i.e. multiple terminal tracks per client call are legal.
- Slice D: define where per-follower `stats_url` comes from (dashboard node record) — currently implicit.

## 5. Architecture / design notes
- Handler-owned `#sse_st{}` + process-dict counter flags confined to the Cowboy process is consistent with the PT-not-cast invariant.
- Atomics-before-listeners in `janus_http_app` is correct; `started_at` ≈ boot is fine given VM-restart reset semantics.
- Dual-repo pairing (TF-6.8/6.8b, nodes.tsx, deploy_prod.sh) is correctly scoped; no catalog/LB invariant is touched.

## 6. Top 5 concrete edits
1. Fix Slice C: command → `rebar3 fmt --check && rebar3 eunit` (PATH), or COPY escript to `/app/rebar3`; pre-fetch fmt plugin in the `test` stage.
2. Specify `finalize_sse(normal)` full frame sequence (pending finish → pending usage → terminator) with defaults for missing stop_reason/tokens, both faces.
3. Rewrite §4.1.4 row 1: in-drain `translate_unsupported` is always provider-origin → 502; 400-after-200 is exclusively mid-stream `n>1`.
4. Define `content_block_start` non-empty-text handling and missing-`message_start` behavior (or remove `role_sent`).
5. State the multi-`track` rule for janus-auto (failed bump gated solely by `janus_stats_failed`) and require comment-line skipping in `sse_events`.
