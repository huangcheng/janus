**2. Critical risks**
- **SSE token plumbing (Chat→Anthropic):** OpenAI delivers `prompt_tokens` only in the final usage chunk — *after* `message_start` has been sent. §4.1.3 fixes `message_start` at `In or 0` and `message_delta` carries only `output_tokens`, so Anthropic clients (Claude Code cost displays) will always see `input_tokens=0` on this face. §10's "late input_tokens" closure covers the Anthropic-*provider* direction, not this one.
- **`include_usage`-ignoring upstreams:** a provider Chat stream may attach `usage` to a choices-bearing final chunk; the mapping only has an "empty-choices usage chunk" arm, so that chunk matches no row.
- **Mid-stream table:** the 400 "client-origin `translate_unsupported` after 200" row is unreachable as written — post-200, only provider bytes can trigger it — and collides with §10's tools→502.
- Counters funnel, volume-staleness wipe, gen0-capture-once, `--code-only` uptime window: adequately specified; no new hole.
