## Defects (ranked)

**D1 — Probe/internal recognition contradicts the tracked-set register (structural seam).** 0.11 pins "Master-side internal recognition = the tracked entry's `Internal` flag", but 0.2/0.11 register only *after a successful reserve counter increment*, and probes "BYPASS pick's reserve loop entirely (no increment, no decrement)" ⇒ probe jobs have **no tracked entry**. Consequences: (a) a probe's `done` falls into "no tracked entry ⇒ drop the sample" — which accidentally gives the right rtt-ingest behavior but for the wrong reason; (b) the **TTFB health-feed exclusion** and the **probe in-flight map clearing** ("cleared on probe done/error", 0.2) have no specified recognition path; (c) if probes *were* registered (`Internal=true` in the track cast exists for somebody), release/purge/reconcile would decrement counters probes never incremented — breaking the pinned counter-neutrality. Pin exactly one: probes stay untracked and recognition = probe in-flight map membership (`{Node => JobRef}`), with release/purge naturally no-op; **or** probes cast `{track,…,Internal=true}` and release/purge/reconcile skip the decrement for `Internal` entries. Also state whether non-probe internal jobs (entitlement probes?) ride the reserve loop — the `Internal` flag in the track cast is otherwise always `false`.

**D2 — `SampledAtMono` write-time comparison is a no-op under master ingest stamps (newly introduced by the rev-8 amendment).** With stamps assigned at ingest in serialized pool handlers, the message being handled *always* has the maximal stamp, so "compare `SampledAtMono` before overwrite" never blocks anything. The claimed property — "protects against out-of-order DELIVERY (a late piggyback cannot clobber a newer row)" — is exactly what ingest stamps cannot deliver: a late-delivered older sample overwrites a newer one (last-arrival-wins). The probe-freshness case is actually protected by the *cold-start-fill-only* rule, not by the stamp. Fix: either drop the claim and pin the true semantics (last-arrival-wins, bounded by the 10 min TTL), or carry a worker-side per-(node, provider) sequence/send-stamp for a meaningful comparison. Also 0.9's "cross-node stamp comparison orders the display cap" is stale — all stamps are now master-side; no cross-node comparison exists.

**D3 — Probe-skip enum not propagated to the pinned surfaces.** 0.2: `reason=cap|cadence|fresh|drained|send_fail` (5). Part C metrics list: `cap|cadence|fresh|drained` (4 — drops `send_fail`). Part C JSON: `{"cap","cadence","fresh"}` (3 — drops `drained`, `send_fail`). 13.4b/eunit assertions on five reasons are not expressible as written.

**D4 — `dispatch_worker_total` label vs JSON key mismatch.** The metric gained `{node, provider}` "making per-provider assertions expressible", but the JSON is `"dispatch_worker_total": {"<node>": int, ...}` — node-only. 13.3b (`{cn-east, provider}` ≥ 1, `{us, provider}` = 0) and 13.6 (Δ`{fast, third-provider}` = 1) need the provider dimension on `/stats/sched`, or the steps must be pinned to `/metrics` explicitly. Suggest `"<node>/<provider>"` keys, as `rtt_ms` already uses.

**D5 — `Result > infinity` correction never landed in the body.** Part C still reads "an atom-vs-number guard would badarg" — the rev-8 correction (Erlang `>` is total-ordered; `number > infinity` is `false`; the skip exists for explicit intent) exists only in the fold header. Body contradicts header.

**D6 — Missing `sched_workers` row ⇒ drained rule absent from the body.** The reserve loop's live re-check (0.6, Part C step 3) never states missing-row semantics. This rule is load-bearing for the post-adopt window (snapshot rows survive in the heir'd table while all `sched_workers` rows are pruned). Add it to 0.6 + Part C + eunit item 4.

**D7 — Exhaustion-reason rule unpinned in the body.** The fold pins "first non-ok outcome in iteration order; drained-pinned ⇒ `drained_pin`", but Part C only says `reason=capacity` generically and `drained_pin` for the single drained-pinned case. Mixed exhaustion (capacity-rollback then live-re-check skips) has no deterministic label — and the non-pinned drained-skip case labels nothing at all.
