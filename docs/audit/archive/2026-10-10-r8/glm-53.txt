## Findings

**F1 — Part C JSON cannot express the new `{provider}` label (surface defect, gate-adjacent).**
Metric: `sched_dispatch_worker_total{node, provider}`. JSON: `"dispatch_worker_total": {"<node>": int, ...}` — node-keyed flat map. 13.3b asserts `{cn-east, provider} ≥ 1` / `{us, provider} = 0` and 13.6 asserts Δ`{fast, third-provider}` = 1 / Δ`{victim, third-provider}` = 0; the pinned JSON shape cannot carry these. Fix: pin the JSON as `"<node>/<provider>": int` (same flattening convention as `rtt_ms`), or pin those two gate assertions to `/metrics` explicitly.

**F2 — `sched_probe_skip_total` enum is stale in Part C (two places).**
Part 0.2 finalizes `cap|cadence|fresh|drained|send_fail`; Part C's metric list omits `send_fail` and Part C's JSON carries only `{"cap","cadence","fresh"}` — missing `drained` and `send_fail`, contradicting the fold's "the JSON key carries ALL five". Fix both lists.

**F3 — The corrected `> infinity` rationale did not land; the false badarg claim survives.**
Part C reserve loop still says "an atom-vs-number guard would badarg". Erlang term order is total: `N > infinity` is `false`, never badarg (this is exactly what the rev-8 fold says was corrected, 3-model concurrence). The skip is right (explicit intent); the justification is wrong and will mislead implementers into thinking it's crash-safety. Replace with the explicitness rationale from the fold header.

**F4 — Tracked-set map shape omits `Internal`, but the narrative depends on it.**
Track cast: `{track, JobRef, Node, ProviderId, ReservedAtMono, Internal}`; Part 0.11 and Part C both write the map as `JobRef => {Node, ReservedAtMono, ProviderId}` — no `Internal`. Yet master-side internal recognition ("the tracked entry's `Internal` flag") is the mechanism behind E.6(b) (internal done-with-`rtt_ms` skipped at ingest) and the usage/Slice-Q story. Pin the value as a 4-tuple in both places.

**F5 — Fold-claimed pins absent from the body:**
- Missing `sched_workers` row ⇒ treated as drained (refuse, safe direction) — nowhere stated; it matters in the post-adopt stale-snapshot window.
- Exhaustion-reason rule ("first non-ok outcome in iteration order; drained-pinned ⇒ `drained_pin`") — 0.6/C cover the two pure cases but not mixed exhaustion (candidate A capacity-rollback + candidate B drained-skip).
- The async locus load result as the ONE sanctioned runtime writer of the `geo_enabled` PT key — implied by 0.1, never pinned.
- Both flush paths advance `snapshot_gen` — Part C attaches gen-advance to the 30 s tick sentence only; 13.2's ≤ 35 s wait leans on the dirty path qualifying too.

**F6 — Fold-claimed eunit cases missing from the Part E enumeration:** adopt → re-hello → snapshot rebuilt → pick dispatches again (claimed as "Eunit 4 extended"; E.4 stops at the ETS-TRANSFER cycle); probe-skip eunit enumerating all five reasons; pinned-path completions DO feed the health EWMA; old-worker `internal` job-map-key tolerance (asserted in 0.10, absent from E.7). Part E is what test authoring follows — add all four.

**F7 — Stale 0.10 sentence contradicts the `sched_v` marker rule.**
"An upgraded master probing a still-old worker is safe (…reports just lack `rtt_ms` until it upgrades)" describes a scenario Part 0.2 now makes impossible (no marker ⇒ not a target). Reword or delete; while there, pin that `FORCE` never bypasses the `sched_v` filter either (its never-bypass list names only cap and dispatchable×enabled).

**F8 — The write-time `SampledAtMono` guard is vacuous as specified; the claimed protection is misattributed.**
With `SampledAtMono` = master ingest stamp and a single serialized writer (done/error/load handlers all in the pool), every processed write is by construction the newest stamp — the compare-before-overwrite is a no-op, and "a late piggyback cannot clobber a newer row" is wrong in direction (a late piggyback clobbers, benignly — passive is canonical). The real protections are (a) the probe cold-start existence gate (probe-after-passive is discarded via "no unexpired row", as the spec itself notes) and (b) handler serialization. Harmless mechanism; fix the sentence so nobody "strengthens" it with cross-node stamps later.
