# Audit — Scheduler v2 spec, rev 8

**Verdict: GO WITH FIXES.** All 16 rev-8 fold items are present in spirit, and none of the findings below touch tier order, demotion math, capacity single-ownership, or the cost floor. But four folds were applied to the rev-header and not consistently to the body, and the new `Internal` flag introduced one genuine mechanism gap. Six must-fix items (all one-or-two-sentence fixes), then minors.

## Spot-checks that pass (verified against the body)

- **Demotion math**: exclude-self threshold is executable at N=2 (victim 8000 vs fast ~500 → threshold max(5000, 1500) = 5000 → demoted; fast threshold 24000 → kept). Min-EWMA survivor invariant holds: for the minimum candidate, 3×median(others) ≥ 3×E_min > E_min, and the 5000 floor can only bind when median(others) < 1667, which is impossible for the minimum candidate — so all-slow ⇒ no demotion, as 13.6's variant claims. N=3 majority-slow arithmetic checks out (median(8000,500)=4250 → threshold 12750 > 8000 → nobody demoted).
- **EWMA seed**: E1=x1 ⇒ three 8000 ms samples read 8000; the seeded-at-0 counterexample (4625 < 5000 floor) is correctly identified.
- **Folds present and coherent**: Part 0.2 target rule as one statement (passive+probe rows, 10-min TTL bound, never-probed oldest, no geo precondition); in-flight exclusion under `cadence`; `sched_v=>2` probe-target gate; send-fail/ack-miss abort with no local fallback for internal jobs; `SampledAtMono` = master ingest stamp with the softened best-effort latest-wins wording; rollback form `{2,-1}`; "measured" ≥ 3 samples on both sides; `geo_disabled_total` explicit-request guard; 13.6 third unpinned provider + quiesce + exactly 3+3 + delta assertions; `JANUS_SCHED_PROBE_MAX_HOURLY=100`; TEST_HOSTS-before-DNS seam; gauge cap removes evicted label sets; error completions write passive rows but not EWMA feeds; piggyback ungated by the master knob; `last_attempt_mono` guard; reconcile deletes reserve+rtt rows; knob-off inertness rollback; Slice-Q bypass at the named filter.

## Must-fix

**F1 — `Internal` flag vs probe lifecycle: shape and semantics don't line up** (Part 0.11, Part C, Part 0.2, Part E.4). Rev 8 pins "master-side internal recognition = the tracked entry's `Internal` flag", but both places that spell the tracked-entry shape still show the 3-tuple `{Node, ReservedAtMono, ProviderId}`. Worse, probes "bypass pick's reserve loop entirely" and are tracked only in the separate pool-state `{Node => JobRef}` map — so if probes never enter the tracked set, the `Internal` flag is dead and the done-handler has no recognizer for skipping rtt ingest/health feed (eunit 6(b) has nothing to assert against). The coherent reading is: `dispatch_probe/2` registers probes in the tracked set with `Internal=true` and no counter increment. If so, three more sentences are required: **release decrement, purge decrement, and the 30 s reconcile's excess math must skip Internal entries** — otherwise probe completions/purges decrement a never-incremented counter and violate the counter-neutrality eunit. Pin the shape as `{Node, ReservedAtMono, ProviderId, Internal}` everywhere, or drop the flag and name the probe in-flight map as the recognizer (accepting that a late done after an ack-miss abort is then unrecognized).

**F2 — `probe_skip` reason enum disagrees in three places.** Part 0.2 pins five (`cap|cadence|fresh|drained|send_fail`); Part C's metric list has four (missing `send_fail`); Part C's JSON has three (`cap`, `cadence`, `fresh` only). The rev-8 fold claims "the JSON key carries ALL five." Update Part C metric enum and the JSON object to all five.

**F3 — `dispatch_worker_total` gained `{provider}` but the JSON surface didn't.** Part C JSON is still `"dispatch_worker_total": {"<node>": int}`, yet 13.3b asserts `{us, provider} = 0` and 13.6 asserts per-provider deltas "on the pinned surface". Either make the JSON shape `{"<node>/<provider>": int}` (the `rtt_ms` pattern) or state explicitly that provider-split assertions read `/metrics`.

**F4 — Part C still carries the false badarg rationale rev 8 corrected.** Reserve-loop text: "when `capacity =:= infinity` the comparison is SKIPPED entirely: an atom-vs-number guard would badarg". Erlang `>` is total-ordered; `number > infinity` is simply `false`. Replace with the corrected rationale (skip exists so intent is explicit), and put it in Part 0.6 where the counter form is pinned, not only Part C.

**F5 — Three rev-8 seam pins never reached the body.** (a) missing `sched_workers` row ⇒ treated as drained (belongs in Part C reserve-loop step 3); (b) exhaustion-reason rule "first non-ok outcome in iteration order" — currently only `capacity` and `drained_pin` are pinned, so an unpinned pick whose candidates all fail the live draining re-check has no assigned reason; (c) Part C says only the 30 s tick advances `snapshot_gen`; the fold said both flush paths do — add it to the dirty-flush sentence (13.2 passes either way, but the spec should say what it means).

**F6 — Keepalive hello: no eunit, and an un-upgraded-worker orphan window.** The 60 s keepalive hello + pool-pid monitor is new worker-side behavior, but Part E item 4 ends at "prunes orphan rows" — the fold-claimed "adopt → re-hello → snapshot rebuilt → pick dispatches again" leg is missing from the eunit list. More importantly, Part 0.10 never addresses: v2 master + still-old workers + a pool-owner-only restart ⇒ adopt prunes all `sched_workers` rows ⇒ old workers (no keepalive, no monitor) never re-hello ⇒ fleet dark until a worker restart or dist reconnect. Deploy restarts the whole node so the practical window is a post-deploy pool crash — narrow, but it must be documented with its closure, and the re-hello leg needs its eunit.
