**1. Verdict**

GO — no two sentences contradict without a §10 winner; remaining issues are gaps, not conflicts.

**2. Critical risks**

- **Drain stall:** only first-byte has a gun timeout (504). No per-chunk receive timeout is specified for the post-200 drain; Cowboy `idle_timeout` does not reliably fire on the response side, so a silent upstream can hang the handler. Spec claims detection via "gun timeout" but never defines one mid-stream.
- **`include_usage` retry vs counters:** undefined interaction. If the pre-retry 400 calls `track(400)`, an ultimately-200 request counts as failed and writes a 400 usage row; Slice B's bump table has no row for this attempt.
- **Disconnect = failed:** internally consistent (track 502), but SPEC §2.4 doesn't say client aborts inflate `requests_failed`; alerting on failed-rate will spike on harmless Ctrl-C.
- **Docker ABI:** named volume masks image `/app/_build`; OTP patch bump without volume wipe = stale beams. CI copies source in, laptop mounts — different build trees; harmless but differs.
- **Deploy wait:** follower passes on `generation > gen0` **or** leader-equal; the first alternative passes on an unrelated interim bump.
- **Protocol:** `n>1` mid-stream 400 is defensive against non-conforming OpenAI proxies; correct, but E2E can't cover it — eunit only (already implied).

**3. Contradictions or stale claims**

None unresolved by §10. Two stale wordings: §4.1.5 test bullet "leftover > 1 MiB → 502" misnames the cap (it's Buffer+Chunk or one `data:` line; the tail alone can't exceed it); Slice C's `test` stage COPY list names "apps + rebar" but build-compile also needs `rebar.config`/`rebar.lock`.

**4. Missing requirements**

- Drain per-chunk timeout value + its finalize reason (→ 502 `upstream`).
- Retry-400 attempt must not `track`/write usage; only terminal outcome counts.
- SPEC §2.4: counters reset on app init; dashboard must tolerate reset (`started_at` exists but reset semantics aren't stated).
- `leftover_cap`/drain-failure frame shape on the Anthropic client face (`api_error` implied, not tabulated).
- TF-6.8 token assertion when upstream omits usage (both-null must be allowed).

**5. Architecture/design notes**

Handler-owned `#sse_st{}` with one leftover owner and pure `translate_sse` is right; keep gun cancel handler-only. Atomics in `persistent_term` before listeners + missing-ref→0 is sound. Dual-repo pairing is correctly mandated; gate script should fail if the dashboard TEST-FLOWS PR is absent.

**6. Top 5 concrete edits**

1. §4.1.4: add drain receive timeout (e.g., 300s) → `finalize({error, upstream})` → 502.
2. Slice B table: retry-400 pre-200 never tracks; only the terminal attempt counts.
3. §4.1.5: rewrite cap test as "Buffer+Chunk or single `data:` line > 1 MiB → `leftover_cap`".
4. Slice C: enumerate `COPY rebar.config rebar.lock apps/ config/` in the `test` stage.
5. §4.4 step 3: require leader-equal generation (drop bare `> gen0`); add counter-reset note to SPEC §2.4.
