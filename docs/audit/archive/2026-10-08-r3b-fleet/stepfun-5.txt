**2. Critical risks**
- **F.7 is untestable as written.** `docker pause` keeps TCP ESTABLISHED — F.4 says nodedown will not fire — so "a peer down (paused) → `{error, noconnection}`" is false until net_ticktime tick-timeout (~60 s); before that erpc raises `timeout`. Use `docker stop`, or explicitly wait past tick-timeout and document the timeout→noconnection transition. The lease-migration claim only works via that same tick-timeout path — state it, or it silently depends on window length.
- **cache_put has no gate and weak mechanics.** No TF-F.* step exercises judge sharing though it changes janus-auto routing fleet-wide. The 4096/sender cap is unenforceable in a hash-keyed local cache (sender not stored); "replay extends by at most one TTL" is asserted, not enforced — a republishing sender extends forever. Blast radius is wrong-tier routing ≤ 300 s, not "duplicate upstream judge calls."
- **The "closed enum" isn't pinned.** `catalog_cache_flush` and lb_cool_clear's local half name no exported function (needs new `janus_lb:clear_cooldown/1`); `janus_config:reload/0` existence unverified; `status/0` is undefined yet erpc'd on possibly-parked/knob-off peers — define it to return `{error, disabled|down}`; wrapper must catch `error:` too, not just exit classes.
- **Quota publisher has no located state.** Which process/ETS holds Slice-Q counters, read how cheaply every 2 s? WindowId alignment assumes ≥ 60 s buckets ("± s vs ≥ 60 s buckets") — verify against the Slice-Q spec.
- **F.4 timing-fragile:** "TTL is the mechanism" holds only while pause < net_ticktime; a longer pause fires tick-timeout nodedown → eager delete. Cap the window explicitly.
