**1. Verdict:** GO WITH FIXES — the contracts (C1–C6) are sound and the ship-unit restructuring resolved the earlier ordering deadlock, but four concrete gaps below must be closed before 1.9 lands.

**2. Critical risks**
- **Interleaved tool deltas → anthropic:** OpenAI chat streams interleave `tool_calls[i]` fragments; anthropic content blocks are strictly sequential. C5 maintains index maps but never mandates buffering/serialization — emitting a second `content_block_start` before closing the first is an invalid anthropic stream. This needs an explicit serializer requirement + interleaved-index fixture.
- **Synthesized responses ids (2.1):** `item_/fc_/msg_` are *exactly* OpenAI's own prefixes. Counter-allocated ids can collide with upstream ids replayed by the mock. Use a distinct namespace (e.g. `janus_…` + attempt nonce).
- **`include_usage` "injection+retry" (C3) is undefined:** some chat-compatible providers 4xx on `stream_options`. Must specify: on rejection, retry without injection and leave usage null (`unreported`), never hard-fail.
- **janus-auto never mentioned:** the adjudicator routes cross-protocol pairs; flipping the knob turns its formerly-400 tool streams into translated streams. No task covers this path.
- Hot-path cost: per-fragment map ops + binary appends on every delta; no overhead budget, only soak counts.

- Decisions says the knob ships "together with **1.3**/2.3" — 1.3 no longer exists (folded into 1.9). Stale.
- 1.9 is physically listed *before* its prerequisites 1.4a–1.8c; a checkbox-driven agent executes top-down. Move it to the end of Phase 1.
