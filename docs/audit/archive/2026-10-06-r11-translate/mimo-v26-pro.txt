**2. Critical risks**
- Lazy emission vs. zero-frame failure: C1 forbids skeleton writes pre-content, yet C4(b) "flushes `response.created` first" on all-fail. The exception is real but unstated as an exception — a state machine implemented literally from C1 will emit a bare `response.failed`, breaking SDKs.
- 4MiB total-content cap is a C5 invariant "for every target", but no checkbox owns implementing it on →chat/→anthropic deferred text (2.4 only covers →responses reconstruction). Ship it and it's never tested; skip it and interleaved deferral is an unbounded-memory DoS.
- `n>1` reject is carried by `stream_translate_tools_enabled` — but 2.3's 2×2 matrix has responses-knob-on/tools-knob-off cells. Does that cell accept `n>1`? Hidden coupling in the one matrix that claims no hidden coupling.
- Spliced synthetic fixtures (>64-calls, truncated) can violate `sequence_number` monotonicity and id-space continuity unless the splice step renumbers; 2.1 asserts strict increase — the corpus builder must state renumbering rules.
- Non-stream `n>1` reject's gating is decided by evidence produced in 1.8, which lands *after* 1.5 — a phase-ordering knot inside Phase 1 itself.
