1. **Verdict: GO** — the spec is internally consistent; every tension I probed (HEX_MIRROR at run vs. the documented run command, uptime-window scope, janus-auto counter funnel) is already adjudicated by §10 or by the surrounding text.

2. **Critical risks**
- **SSE translate contracts:** the `#sse_st{}` field set is rich (block/next_block/usage_sent/finish_sent/terminal_sent); the dual "usage on `message_delta`" (Anthropic face) vs. "empty-choices usage chunk" (Chat face) asymmetry is the highest bug-density area. The eunit-first list in §4.1.5 is adequate but thin on block-transition cases (text→thinking within one chunk, §4.1.3 "content first, then reasoning").
- **Mid-stream errors:** status stays 200 while `track` records 400/502 — correct, but dashboard consumers of usage/stats must not treat wire-200 as success; worth one sentence in SPEC §2.4 (Slice B already touches it).
- **Cowboy idle/disconnect:** relying on `stream_body` error/EXIT as the sole disconnect detector is sound only if gun timeouts also surface as handler-visible errors on a stalled-but-open upstream; the spec states this but no E2E asserts it (TF-6.8/6.8b are happy-path).
- **Docker/_build ABI:** named-volume `_build` reuse across OTP/rebar.lock changes is guarded by "recreate the volume" documentation only — a stale-beam failure mode with no automated guard (e.g., a marker file checked at RUN start).
- **Deploy wait:** follower-poll uses dashboard-DB `gen0` but leader generation captured post-catalog-apply; a config ship landing *during* the window between gen0 read and leader apply would false-pass followers on the ">gen0" disjunct. Low probability, undetected by design.

3. **Contradictions or stale claims**
None found that §10 does not resolve. §4.3's "HEX_MIRROR on build **and** run" vs. the run command block lacking `-e HEX_MIRROR` is settled by §10 ("HEX_MIRROR **at build**") plus the warmed hex cache; the "and run" clause is dead text, not a live contradiction.

4. **Missing requirements**
- No E2E or eunit for disconnect/`stream_body {error, closed}` producing exactly one usage row with null tokens and a 502 track (§4.1.4's most stateful path).
- No fixture realism note for Anthropic `message_start` with *missing* `usage` (§4.1.3 says "omit if missing, never crash") — add one binary-key eunit case.
- Slice C: no `priv/` mount discussion (harmless today since `apps/` includes `priv/`, but the file-touch map should say so); no guard against stale `_build` volume beyond docs.
- Slice B: `/stats` uptime/started_at emitted, but SPEC §2.4 update does not state counter reset semantics (app restart → 0) for dashboard readers.

5. **Architecture/design notes**
- Handler-owned `#sse_st{}` with `Rest`→`leftover` as sole owner is the right shape; keeping `gun:cancel` handler-only preserves the single-finalize invariant.
- Process-dict flags (`janus_stats_counted/tracked/failed/inner`) on the Cowboy process only, with inner put/erase scoped by `after`, is consistent with the existing persistent_term-over-casts invariant.
- Atomics created pre-listener in `janus_http_app` respects boot ordering; read-missing→0 is safe.
- Dual-repo pairing (A↔TEST-FLOWS, D↔deploy_prod.sh) is correctly enforced by the "Janus-only merge does not close the slice" rule.

6. **Top 5 concrete edits**
1. Delete "and run" from §4.3's HEX_MIRROR sentence, or add `-e HEX_MIRROR` to the documented `docker run`.
2. Add eunit cases: text→thinking transition in one chunk (content-first ordering), and `message_start` without `usage`.
3. Add a TEST-FLOWS entry (or extend TF-6.8) asserting client-disconnect → one usage row, null-token tolerant, `track` 502, no double finalize.
4. Slice C: add a `_build`-volume staleness marker (OTP version + `rebar.lock` hash written at compile; RUN aborts on mismatch) instead of doc-only wipe instructions.
5. SPEC §2.4 edit: state explicitly that counters reset on gateway app restart and that wire-200 streams may still record 4xx/5xx in `requests_failed`.
