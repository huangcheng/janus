## 1. Verdict
**GO WITH FIXES** — core design is sound and honest about trade-offs, but probe-row accounting in the new reconcile guard, caller-side write ordering, and the schema_version bump need pinning before ratification.

## 2. Critical risks
- **B.1 reconcile vs `sched_tracked` must exclude `Internal=true` probe rows.** Probes insert tracked rows but never reserve; if the two-tick guard compares raw counts, reserve < tracked reads as negative drift and the guard "heals" reserve upward — capacity corruption from a bookkeeping table.
- **Caller-side write order unpinned.** Pick must bump `sched_reserve` with the pinned 4-tuple `ets:update_counter/4` form FIRST and only insert the tracked row on success (bump failure ⇒ try next candidate); release = `ets:take` then pinned-form decrement. The 5-tuple ban must be restated for these new writers or B.1 reintroduces the wrap bug.
- **Drain-idle on reserve=0 is not equivalent under reconcile.** A downward heal on a draining node can hit 0 while jobs still run, arming the sticky timer early. Arm on the node's tracked-set emptiness, not the counter.
- **schema_version 1→2 contradicts "additive."** Additive keys don't require a bump; the bump breaks existing pinned gate/eunit assertions and any consumer. Pick one: keep 1, or enumerate every fixture that flips.

## 3. Contradictions or stale claims
- C.3's boot counter is only useful if /metrics is scraped — prod scrapes nothing today (the eval itself noticed zero prometheus rendering). A boot-time counter invisible in /stats/sched is surface without surface.
- F claims "no log scraping," but C.3's warning is log-only; only the counter half is falsifiable by its own gate rules.
