**Verdict: GO WITH FIXES** — architecture is sound; deny-regex, race semantics, streaming boundary, and 429 handling need tightening before implementation.

**Critical risks**

1. **Deny-regex false-negatives on Chinese providers.** Zhipu/Ark/DashScope return errors in Chinese; `/not activated|no permission|.../i` matches zero rows. Every CN-region model becomes permanently `unknown` and is picked on every request — defeating the pre-filter.

2. **Streaming "first byte" is under-specified.** Anthropic `event: ping`, OpenAI `[DONE]`, SSE comments all send transport-level bytes before content. If "first byte sent to client" = transport byte, half-collected re-attempt duplicates pay-per-token cost on the same prompt. Define boundary as "first SSE data event with non-empty delta flushed downstream"; forbid re-attempt once any token has been emitted.

3. **Catalog reload race.** Probe bumps `generation`; gateway may pull mid-request. Attempt 1 picks a deny-key (matrix not yet loaded), attempt 2 picks the same deny-key (still same poll). Confirm `janus_catalog` does atomic one-shot swap, not per-row mutation, and that `bump_generation` follows committed matrix write in the same transaction.

4. **429 conflation.** Rate-limit (recovers in seconds) and balance-exhausted (recovers in hours) share one cooling curve — a brief rate-limit burst cools every model on that key for hours. Split: rate-limit → short cooldown honoring Retry-After; balance → long cooldown.

5. **Probe rate-limit blowback.** 5 concurrent × 786 DashScope requests sweeps hourly caps. Auto-probe exhausts the cap, then 429-rate-limit writes poison `balance` rows. Per-provider circuit-breaker and Retry-After honoring required.

**Contradictions**

- A.3 "never downgrade ok→deny unless deny evidence is newer" ties on `now()`; two concurrent writers tie and last-write is non-deterministic. Replace timestamp with per-(key_id, model) monotonic version column.
- B SQL ships `ok` rows that are dropped on the gateway side. Dead bytes on the wire.

**Missing requirements**

- New key added between syncs has no probe trigger — coverage hole until next sync.
- Probe network egress: region-pinned providers (Bedrock, Vertex) require probe to match gateway egress, or matrix is wrong.
- Per-attempt usage triples DB write load on hot paths; `janus_usage` batching not addressed.
- All-3-keys-401 short-circuit: spec burns 3 × 60s before returning; should short-circuit when the pool is uniformly auth-broken.

**Design notes**

- Successful-fallback cooling: attempt-1 fail + attempt-2 success cools attempt-1's key. Document explicitly so operators don't double-cooldown.
- 3 × 60s TTFB = 180s within 300s cowboy idle timeout — document as worst-case budget.
- `pick_listing_route` matrix lookup uses canonical model name; confirm alias normalization before deny-map lookup.

**Top 5 edits**

1. Replace deny-regex with per-provider error-vocabulary table; require CN-locale strings.
2. Specify stream-failover boundary as "first SSE data event with non-empty delta flushed downstream".
3. Resolve passive-learning ties via per-(key_id, model) monotonic version, not timestamp.
4. Split 429: rate-limit → short cooldown honoring Retry-After; balance → long cooldown.
5. Add per-provider circuit-breaker + Retry-After to probe runner; back off after 3 consecutive rate-limit hits.
