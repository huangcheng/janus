**1. Verdict: GO WITH FIXES** — the plane split is sound, but the passive-learning writer, matrix table ownership, and stream-retry boundary are ambiguous enough to ship bugs.

**2. Critical risks**
- Probe blowback: ~786 requests at 5/provider can itself trigger 429s, which A.2 cannot reliably distinguish from `balance` (free-text regex) → mass misclassification.
- False negatives: 404→`deny` is wrong for providers that 404 transient routes; 401/403 aborts the probe as "key broken" yet C.1 calls it retryable — inconsistent evidence model.
- Latency: worst case 3×60s TTFB + one 5xx retry; no total request deadline.
- Retry storms: 3× usage rows per request; unless cooldown is applied synchronously before re-pick, `pick_route` returns the same failing key.
- Streaming boundary: HTTP status/headers may already be flushed; "before first client byte" must mean buffering status+headers too.

**3. Contradictions / stale claims**
- A.1: gateway writes `source='traffic'` rows; A.3/Part C: dashboard folds usage rows. Pick one writer.
- A.3's fold rules omit 429→`balance`, yet C.1 says balance keys "learn" from traffic.
- "`unknown` written when a pair is first seen" — no component ever writes `unknown`.
- `key_entitlements` is "dashboard-owned (ensure_schema)" yet `janus_db_conn` SELECTs it — shared Postgres? Which migrations dir? SQLite path?

**4. Missing requirements**
- Explicit judge-bypass flag for the shared `do_proxy` loop (C.3 claims "no changes" but janus-auto must skip it).
- Total request deadline; balance-row re-probe cadence (7-day TTL keeps a replenished key dead for a week).
- Refresher single-flight/locking (on-demand + post-poll triggers race).
- Retention of `http_status`/`error_code` for A.5 bind-rejection evidence (bundle ships status only — fine, but say it).
- Interaction rule: `failover_max_attempts=0` vs. matrix pre-filter (does pre-filter survive?).

**5. Architecture/design notes**
- ETS rebuild is atomic per table, but matrix and routes can straddle generations; rebuild both in one insert pass or version them together.
- Usage-row-per-attempt ≈ 3× load on `janus_usage`; verify batch writer headroom.
- Last-write-wins on `checked_at` only works if timestamps are usage event time, not fold time.
- Deny regex is English-text-bound (DashScope/Ark may return codes or Chinese text); use per-provider error-code tables with regex fallback.
- Cooling: attempt counter and exclusions must be evaluated at pick time, not post-pick.

**6. Top 5 edits**
1. Name the dashboard refresher as sole traffic writer; add 429→`balance` mapping.
2. Decide table ownership: shared DB + gateway migration, or a fetch path — now.
3. Specify pre-first-byte buffering (status+headers) as the retry boundary.
4. Add total deadline + synchronous cooldown before re-pick.
5. Error-code-first classification with regex fallback; short TTL/re-probe for `balance`.
