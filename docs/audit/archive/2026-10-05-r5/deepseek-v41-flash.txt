## 1. Verdict
**GO WITH FIXES** — direction is sound, but i18n classification, SQLite/catalog-fetch safety, and generation-bump thrash must be resolved before implementation.

## 2. Critical risks
- **Probe blowback.** 262 models × 3 keys ≈ 786 requests per DashScope sweep; "throttle concurrency" is unspecified, and 429-rate → "leave previous state" means coverage never converges on rate-limited providers. No cost/rate budget, no per-provider opt-out, and A.4 makes it recurring after every sync.
- **Classification false-negatives.** The deny regex is English-only. DashScope/zhipu emit Chinese (`未开通`, `无权限`); a real denial becomes `ok` with `source='probe'` — the exact inverse of the uni-api bug cited. 429 balance-vs-rate is likewise text-based.
- **Generation thrash.** Per-row probe writes bumping generation ⇒ up to 786 catalog rebuilds per sweep. Batched-bump contract is absent.
- **Retry amplification.** 401/403 get 3 attempts; a revoked key makes every in-flight request retry 3× against an already-failing provider, with no LB-cooldown collapse.
- **Key rotation.** In-place secret rotation keeps `provider_key_id`, so stale entitlements attach to the new secret. No invalidation hook.
- **Streaming boundary.** Mid-collect failed attempts need usage rows with unknown token counts; interaction with `collect_drain` is unverified.

## 3. Contradictions / stale claims
- A.1 says `unknown` is "written when first seen", but no writer exists; absence already means unknown ⇒ dead state.
- C.1 says `balance` "fails over once, learns", yet the pre-filter excludes balance keys ⇒ never picked, never fails over.
- E2E #4 (4xx row for deny key) vs #9 (no row for deny key) are contradictory unless labeled matrix-off/on.
- `deny_keys_by_model: ModelName => KeyId` lacks model-name normalization (case/version suffixes).

## 4. Missing requirements
- **Dialect safety:** `now() - interval '7 days'` is invalid on SQLite; if `key_entitlements` is absent on a sqlite gateway the whole catalog fetch fails → boot failure. Needs dashboard-owned migration + gateway-tolerant fetch.
- Authz/audit/rate-limit on the new probe endpoints; single-flight for the fan-out endpoint.
- Stale semantics for `balance` (TTL currently only covers `ok`/`deny`).
- `failover_max_attempts` read path must be persistent_term (invariant), not a cast.
- Attempt idempotency key on usage rows.

## 5. Architecture notes
- ETS whole-map swap is fine; per-request reads during rebuild are fail-safe (missing = eligible) — state it explicitly.
- Usage-row-per-attempt multiplies the usage pipeline and passive-learning fold; add `attempt_index`/dedupe key.
- Passive-learning races: dashboard fold and gateway traffic rows both write `checked_at`; last-write-wins can resurrect a stale `ok`. Order by evidence recency.
- 429 dual meaning is unavoidable without provider error catalogs — accept, but log unmatched shapes.
- Unmatched 400s must write `unknown`, never silent `ok`.

## 6. Top 5 edits
1. Provider-configurable + zh-aware classification; unmatched 400 → `unknown`, logged.
2. Dialect-safe bundle SQL; tolerate missing table.
3. One generation bump per probe batch.
4. Cap 401/403 retries (or collapse via LB); define probe concurrency/backoff/budget.
5. Resolve balance contradiction; invalidate on secret rotation; add `attempt_id`.
