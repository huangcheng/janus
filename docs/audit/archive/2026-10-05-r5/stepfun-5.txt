## 1. Verdict

**GO WITH FIXES** — the split (probe/matrix in dashboard, consumption/failover in gateway) is right, but probe misclassification (endpoint shapes, 400-vs-404 deny signals, English-only regex) and failover storm/eligibility edges will cause self-inflicted outages.

## 2. Critical risks

- **Probe cost/rate-limit blowback:** 786 probes at concurrency 5 against a provider whose TPM may be shared account-wide trips the very limits being measured; "a few cents" is optimistic (min billing units). A.4's post-sync sweep compounds on-demand probes.
- **Classification false-negatives:** (a) zhipu coding-plan keys 404 on the chat endpoint → probe writes `deny 0/K` → key permanently excluded — the exact case named in the Goal. (b) Providers returning 400 `InvalidModel` or Chinese error text miss the English regex → misread as `ok`/`input_shape` (the historical uni-api bug, reintroduced via 400→ok).
- **Failover latency amplification:** 3 × 60s TTFB = 180s vs typical agent client timeouts (60–120s): clients see timeouts, not failover.
- **Retry storms:** client concurrency × 3 during a provider incident; nothing cools the *provider* after exhaustion.
- **Catalog reload race:** acceptable only if `janus_catalog` rebuild is an atomic state-swap landing deny-map and routes in the same generation — verify, don't assume.
- **Matrix staleness during rotation:** a `deny` key is never picked → never earns a traffic-sourced 200 → never re-learns; up to 7 days of half-capacity pool after the operator re-enables the key provider-side.
- **Streaming boundary:** handled correctly (error-status pre-first-byte retryable).

## 3. Contradictions / stale claims

- `dispatch/7` (C.1): verify current arity/signature.
- A.3 assumes usage events carry `provider_key_id` + error shape; if the usage table lacks these columns, passive learning is unimplementable as written.
- "Probe must NOT route through the gateway" contradicts needing per-provider `base_url`/endpoint logic (Ark, zhipu) — bypassing the gateway bypasses provider quirks.
- "No new state in janus_lb" vs. a pre-filter that must evaluate denied + balance + cooled eligibility at every pick.

## 4. Missing requirements

- Provider-scoped cooldown/circuit-breaker after failover exhaustion.
- Defined pick behavior when zero keys are eligible (hard error vs. degraded least-recently-failed).
- Immediate re-probe trigger on observed key-level 401.
- Usage-row attempt numbering (billing double-count risk).
- Where `janus.failover_max_attempts` is defined — must be settings-table/PT-driven, not `sys.config`; plus rollout semantics for gateways with no matrix (absence = eligible — state explicitly).
- Shorter deny-row re-verify TTL than 7 days.

## 5. Architecture notes

- **ETS rebuild:** confirm atomic swap; deny map must not update independently of routes.
- **429 dual meaning:** cap *consecutive* 429-failovers at one; account-shared TPM looks per-key from inside.
- **Passive-learning races:** last-write-wins must be in SQL (`ON CONFLICT … DO UPDATE … WHERE checked_at < excluded.checked_at`), same DB clock for probe and traffic writers — not app-level comparison.
- **max-attempts × cooling:** eligibility = not denied ∧ not balance ∧ not cooled; exhausted-but-all-cooled must degrade, not loop.

## 6. Top 5 concrete edits

1. Probe replicates each key's configured base_url/endpoint (add coding-endpoint shape where required); classify deny via provider **error_code lists first**, regex as fallback; never 400→`ok` without an explicit code whitelist.
2. Guarded SQL upsert for all matrix writes; add 401-triggered re-probe; deny rows re-verified at 48h regardless of the 7-day bundle filter.
3. Provider-level circuit after exhaustion; max one 429-failover per request; zero-eligible-keys → least-recently-failed pick, single attempt.
4. Usage schema gains `attempt_index`, `provider_key_id`, `error_code`; `/api/usage` billing counts only the final attempt.
5. Declare `failover_max_attempts` as a settings-table key (PT, default 3, 0 disables); spec mixed-version fleets (missing matrix = no deny map) and that the knob rides the existing generation-poll path.
