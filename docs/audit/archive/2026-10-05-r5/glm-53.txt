**1. Verdict: GO WITH FIXES** — sound architecture (matrix via existing generation-poll, no new RPC), but the probe classifier and balance-state lifecycle ship the spec's own motivating bugs.

**2. Critical risks**
- **Endpoint-variant keys**: zhipu coding-plan keys (the spec's own evidence) only work on the coding endpoint; probing the default endpoint yields 404 → `deny` for *every* model → bind validation rejects a usable key. Probes must be per-key endpoint-aware or such keys excluded from v1.
- **Deny regex is English-only**; DashScope/Ark/zhipu return Chinese errors ("未开通/无权限"). A Chinese 400 misses the regex → classified `ok/input_shape` — exactly the historical uni-api bug, reintroduced. Classify on provider `code` fields, not text; unmapped 400 → `unknown`, never `ok`.
- **Balance deadlock**: Part B/C exclude `balance` keys from picking, but A.3 recovers only via traffic or manual probe. An excluded key never earns traffic → stuck up to 7 days. No re-probe schedule for `balance`.
- **Latency/storms**: 3 attempts × 60s TTFB approaches Cowboy's 300s idle_timeout and blows agent-side timeouts; retrying 429 (rate) across keys triples volume against an org-wide quota. No wall-clock budget, no provider-level breaker.
- **model_name namespace unpinned**: probe uses listing names; usage rows may carry requested/translated model names. Mismatch silently pollutes the matrix.

**3. Contradictions / stale claims**
- A.1: "balance failing over once is acceptable" vs B/C excluding balance keys entirely (never attempted).
- C.1 pseudocode `attempts < 3` starting at 0 permits 4 total attempts; §C.2 says max 3 — off-by-one ambiguity test 5 can't pin.
- Bundle SQL uses `now() - interval '7 days'`/TIMESTAMPTZ — Postgres-only; esqlite gateways break (repo supports both).

**4. Missing requirements**
- How `janus.failover_max_attempts` reaches gateways (must be settings → persistent_term per invariant).
- Per-attempt usage rows need attempt-index + request correlation or debugging/billing is unreadable.
- Gateway failover metrics (attempts histogram, retry reasons).
- Probe scope: probing all 262 listings weekly burns ~750 requests/key for ~15 callable; limit to bound + router-candidate models.
- 429-balance is never learned from traffic (A.3 folds only 200/400/404).

**5. Architecture notes**
- ETS atomic swap of routes+matrix in one bundle is correct — keep it; per-request reads see a consistent generation.
- "More eligible keys remain" undefined when all keys cool mid-loop — define terminal behavior.
- Probe-vs-refresher upserts race on `checked_at`; single dashboard clock makes LWW safe, but batched read-then-write can revert newer evidence — recheck timestamp in the UPDATE predicate.

**6. Top 5 edits**
1. Per-key endpoint/base_url in probes; else exclude endpoint-variant keys from v1.
2. Error-code-based classification table per provider; unmapped 400 → `unknown`.
3. Scheduled `balance` re-probe (e.g. 1h) or canary traffic; fix the A.1/B inconsistency.
4. Pin `model_name = listing name` across probe, usage rows, bundle; attempt index on usage rows.
5. Total failover deadline + provider 429 breaker; clarify attempts semantics; SQLite-compatible bundle SQL.
