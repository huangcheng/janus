**1. Verdict:** GO WITH FIXES — the spec is unusually tight on SSE state and error contracts, but usage double-accounting, the `_build` volume shadowing the image, and the deploy generation wait's vacuity on no-config ships need pinning before implementation.

**2. Critical risks**

- **Usage double-count (Slice A):** "Usage capture stays on provider bytes via `capture_usage_chunk`" while `#sse_st{}` *also* merges `message_start`/`message_delta` tokens to synthesize the client usage chunk. Two token pipelines on the same stream will drift or double-write the usage row. Spec never says which is authoritative.
- **`_build` ABI/volume (Slice C):** `janus-ebin-otp27:/app/_build` **shadows** the image's precompiled `_build`, so the in-image `./rebar3 compile` is wasted on the documented laptop path, and first-run must reach **hex.pm** — only apk is Aliyun-mirrored. China laptops may hang on hex exactly like apk did.
- **Deploy generation wait (Slice D):** step 3 requires follower `generation > gen0`, but nothing guarantees a deploy bumps generation. A code-only ship with an unchanged `settings` row makes the wait fail (or the `> gen0` clause is dead code). The "code-only ship" escape clause contradicts steps 2–3.
- **janus-auto counter semantics (Slice B):** "janus-auto = 1" but inner judge/target calls presumably re-enter `do_proxy`. The bypass point for the "single funnel" is undefined — risk of total counting 3 and failed counting 1, or worse, failed > total.

**3. Contradictions / stale claims**

- §4.1.4 client disconnect: "no further frames" yet "`finalize_sse(disconnect)` internally" — the signature returns frames; spec must state they're discarded.
- §4.1.2 "Every arm returns St. Bare `skip` forbidden" vs. mapping table repeatedly saying `{ok, [], St}` — fine, but `message_delta` "No usage on this chunk" conflicts with "when out_tokens known **or on message_stop**" if `message_delta` carries the only `output_tokens`.
- Native path "do not otherwise change bytes" vs. adding `x-accel-buffering` — that's a header change; harmless but contradicts "byte-identical" in §4.1.2.

**4. Missing requirements**

- No backpressure/flow-control story: `cowboy_req:stream_body` blocking vs. gun `active` socket; provider line-length cap (leftover cap covers accumulation, not a single 10 MiB `data:` line).
- No contract for `content_block_start` with **non-zero index gaps** or interleaved blocks from upstream.
- Slice B: no statement on atomics size/reset (restart resets — say so); SPEC §2.4 field types unverified here.
- E2E: no fixture for the mid-stream `error` event or leftover-cap path at the E2E level (eunit-only).

**5. Architecture notes**

- Handler-owned `#sse_st{}` in the same process as `janus_usage_head` is sound; drain callback folding `translate_sse` per event keeps backpressure natural — good.
- `persistent_term` atomics before listeners matches the boot-order invariant.
- Paired TEST-FLOWS PR rule is correctly enforced; TF-6.8b's "last event `message_stop`" should also assert `event:` line presence per frame.

**6. Top 5 concrete edits**

1. Declare one token authority: `#sse_st{}` merge writes the usage row; `capture_usage_chunk` disabled on translating streams (or vice versa).
2. `finalize_sse(disconnect)` → `{ok, [], St}` explicitly; document frames are unwritable after `stream_body` `{error, closed}`.
3. Slice C: either copy image `_build` into the volume on first run (`test -d _build/default || cp -r`) or drop in-image compile; add `HEX_MIRROR`/repo mirror for hex.
4. Slice B: name the exact janus-auto inner-call bypass (e.g., `put(janus_stats_counted, true)` pre-set by the adjudicator) to keep `failed <= total`.
5. Slice D: replace `generation > gen0` with "equal to captured leader generation on two consecutive polls", and state the dashboard **always** bumps generation on deploy — else skip the wait via an explicit `--code-only` flag.
