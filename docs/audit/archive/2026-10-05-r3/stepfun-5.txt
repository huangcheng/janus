# Audit — Janus next-phase design spec

**1. Verdict:** GO WITH FIXES — the contracts are unusually precise and mostly self-consistent, but usage-accounting ownership, late prompt-token emission, counter crash semantics, and Docker volume invalidation must be pinned down before code starts.

**2. Critical risks**
- **SSE mapping:** (a) Chat→Anthropic drops late `input_tokens` if `message_start` emitted 0 — Claude Code will display wrong usage; (b) real Anthropic pairs `thinking_delta` with `signature_delta`; omitting signature is unverified against Claude Code; (c) real Anthropic terminates on `event: error` — no `message_stop`; the invented `message_stop` may confuse clients; (d) `finish_reason=tool_calls` without deltas errors mid-stream — map to `stop` + log.
- **Mid-stream errors:** usage-row ownership is ambiguous — "synthesized usage on the client stream" vs "capture on provider bytes" both appear; there must be exactly one path (provider bytes) or TF-6.8 tokens stay null. Every `stream_body` write needs an explicit `{error, closed}` catch → disconnect finalize; the `after` clause must flush usage even when Cowboy kills the handler.
- **Counters:** handler crash → `failed` inflates HTTP failure rate — must be declared in UI. Responses/Messages native faces and janus-auto must not bypass `do_proxy` or counts silently miss.
- **Docker:** named volume survives image/dep updates → stale `_build`; no invalidation documented; host-vs-image `rebar.lock` drift unhandled.
- **Deploy:** `gen0` read timing relative to ship start unspecified; code-only success ("new VM") lacks a named restart source.
- **Protocol compat:** `reasoning_content` on Chat face is de-facto (DeepSeek) — fine.

**3. Contradictions / stale:** none outright. `created` (unix seconds) source unspecified; error table conflates client-400 and provider-502 under "same JSON" (statuses differ — already in the `track` column).

**4. Missing requirements**
- Counter funnel verification: all client faces + janus-auto counted exactly once.
- `janus_usage_parse` must key Anthropic SSE usage merge on **provider** protocol, not client.
- Behavior when one frame >1 MiB (never-flushing leftover vs cap-excess error).
- E2E: assert `failed <= total`, target the **serving** node, and add token not-null assertion to TF-6.8b.

**5. Architecture notes:** per-handler `#sse_st{}` with single finalize/cancel point in `try…after` is the right invariant; usage head co-located in the handler process is right; atomics pre-listener via `persistent_term` is correct; namespaced process-dict keys are correct. Counter order must be `inc_total` → `put(counted)` — reverse breaks `failed <= total` on crash windows. LB/catalog untouched.

**6. Top 5 concrete edits**
1. State one usage path: provider bytes → `janus_usage_parse`; client usage chunk is display-only; add token asserts to TF-6.8b and confirm merge (Slice B footnote in §7).
2. Emit **merged** input+output tokens in Anthropic `message_delta` and in the final Chat usage chunk (never lose late prompt tokens).
3. Freeze counter order + document "failed includes handler crashes" for the Nodes table; add E2E invariant `failed <= total`; verify all faces enter `do_proxy`.
4. Docker: document `volume rm janus-ebin-otp27` (or hash-suffixed name) on `rebar.lock`/OTP/image change; ensure `test` stage compiles with hex fetched so CI eunit needs no `get-deps`.
5. `deploy_prod.sh`: record `gen0` **before** any ship action; define code-only success from a named uptime/restart source; treat Anthropic `error` as terminal without `message_stop` unless TF-6.8b proves Claude Code requires it.
