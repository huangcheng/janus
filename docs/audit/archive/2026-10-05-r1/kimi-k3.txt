# Audit: Janus next-phase spec

## 1. Verdict
**GO WITH FIXES** — the three-slice phasing is sound, but the SSE event-mapping contract, counter bump points, and image-stage naming are under-specified enough to ship bugs the project has shipped before.

## 2. Critical risks

- **SSE translate contracts**: No event-mapping table. Anthropic SSE is `event:`-named (`message_start`, `content_block_start/delta/stop`, `message_delta`, `message_stop`, `ping`, `error`); OpenAI is bare `data:` chunks + `[DONE]`. Undefined: who synthesizes `[DONE]`, role-chunk emission from `message_start`, `content_block_start` carrying a full `tool_use` (not a delta), `ping` passthrough/drop, and finish_reason mapping (`end_turn`→`stop`, `max_tokens`→`length`).
- **Usage asymmetry**: OpenAI stream usage requires `stream_options.include_usage=true`; Anthropic splits usage across `message_start`/`message_delta`. If provider is Anthropic and client is OpenAI Chat, does the bridge synthesize a terminal usage chunk? Unspecified — clients will see divergent token reporting.
- **Mid-stream errors**: Once 200 + SSE headers are committed, `track(400)` on `translate_unsupported` mislabels the terminal status; error frame shape per client protocol is undefined.
- **Counter semantics**: "attempted routing" vs "recorded status ≥400" will double-count or under-count. Client-caused 400s (bad JSON parse succeeds, translate rejects) currently count as failed — contradicts "not our upstream failure" rationale used to exclude 401s. Crash path: who increments if the handler dies before `track/3`?
- **Docker/ABI**: `-v F:/Janus:/app` hides the image's compiled `_build`; the named volume fixes that, but CRLF checkout will break `fmt --check` in-container. Also `docs/` and AGENTS.md already document `--target build -t janus-build:test`; the spec renames the stage but keeps the tag — guaranteed doc rot.
- **Deploy generation wait**: no timeout value, no poll-interval vs gateway-poll-cadence analysis, no fail behavior (halt? roll back leader?).

## 3. Contradictions / stale claims

- §4.1 says usage comes only from provider bytes, but nothing states whether translated client SSE carries usage — silent behavioral fork.
- §4.2 counts failures at `track/3` yet lists "crash" as a failure source; a crashed handler never reaches `track/3`.
- "CI green ≠ laptop green" (§2) is only half-fixed by the *optional* `eunit-docker` job (§4.3).

## 4. Missing requirements

Explicit bidirectional event table; error-frame JSON shapes; `[DONE]`/`message_stop` synthesis rules; `include_usage` forwarding policy; counter single-bump-point definition + in-flight disconnect handling; exact mount command (source + named `_build` volume + autocrlf note); deploy wait timeout/interval/abort semantics; TF-6.8 fixture shapes (binary keys, SMALLINT — the project's historical bug class).

## 5. Architecture notes

Handler-process state (leftover bytes, open block index) matches existing `janus_usage_head/tail` placement — correct. Atomics-in-persistent_term matches `janus_usage` drops — correct. Keeping provider-side `call_adapter` native preserves LB/cooldown invariants. Editing TEST-FLOWS in the dashboard repo is right.

## 6. Top 5 edits

1. Add the full SSE event-mapping table (both directions, incl. thinking, tool_use, ping, error, terminal frames, usage synthesis).
2. Define counters: one bump point for `total` post-auth/post-parse; `failed` only in `track/3`; exclude client 4xx; specify disconnect/crash handling.
3. Specify mid-stream error contract: protocol-shaped error frame; terminal status recorded as 502/closed, not 400, once headers sent.
4. Reconcile image stage/tag with existing docs (extend `build` or rename everywhere); add the exact Windows mount command + CRLF caveat.
5. Quantify deploy wait: timeout, poll cadence vs generation poll, halt-don't-rollback behavior, and where the stats-token check runs.
