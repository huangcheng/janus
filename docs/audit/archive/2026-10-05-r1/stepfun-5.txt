**Verdict:** GO WITH FIXES — the phased decomposition and invariants are sound, but the SSE contract, counter funnel, request-leg translation, and the two conflicting local-eunit recipes will cause rework or false green if unaddressed.

**Critical risks**
- **SSE contract unpinned.** No event mapping table. The two protocols differ structurally: Anthropic requires `message_start → content_block_start/delta/stop → message_delta → message_stop` and emits `ping`; OpenAI (non-Responses) streams usage-only chunks with empty `choices` and only sends terminal usage with `stream_options.include_usage`. TF-6.8's "(or `message_stop`)" hedge is exactly the drift this causes.
- **Usage placement.** "Usage on the terminal event" is wrong for Anthropic: `input_tokens` land in `message_start`, `output_tokens` in `message_delta` — a merge rule is required.
- **Mid-stream failure.** After a 200 with headers sent, `track(400)` conflicts with recording status; define protocol-shaped error frames (Anthropic `error` event; OpenAI `data:{"error":…}`) and what status `track` stores.
- **Missing request leg.** Chat→Anthropic streaming must first translate the *request* (with `stream:true`); request-side `translate_unsupported` (image) must 400 before touching upstream — no table row covers this.
- **Docker.** AGENTS.md documents `--target build` no-mount; §4.3 documents mount + named volume — pick one. Worse: unless the stage purges `_build` (or `.dockerignore` exists), host `_build` (wrong ABI) gets *baked into the image*; the volume only protects runtime.
- **Counters.** Two independent sites (total at attempt, failed at exit) with fuzzy exit coverage invite drift; decode-failure 400s silently excluded.
- **Deploy.** "Equals leader" has no timeout value; leader's own generation unverified.

**Contradictions / stale claims**
- Two documented local eunit commands (AGENTS.md vs §4.3).
- `translate_sse_chunk/3` vs `translate_sse/3` for one function.
- File map omits `../janus-dashboard/` prefix on `spa/src/pages/nodes.tsx`.
- §4.2's opening sentence self-contradicts after defining exclusions.

**Missing requirements**
Event mapping tables (both directions, ping/usage-only handling); mid-stream error/status contract; pre-flight 400 on request-translate failure; per-protocol usage merge; eunit for unknown-field skip, malformed JSON, usage merge; negative + reverse-direction E2E; explicit counter funnel path list; `_build` purge in stage; TF numbering coordination across the dual repo. §5.2's "already an invariant" on `pick_route` is asserted without evidence.

**Architecture notes**
Per-connection handler state is the right home for leftover bytes / open block index / role flag. Atomics in persistent_term are VM-global, not "process-local" — cosmetic, but the comment should say so; boot-relative counters are an accepted limitation. On client disconnect, abort the upstream request too, not just the handler. The translate path must leave `pick_route` and cooldown semantics untouched (drain-error cooldown preserved).

**Top 5 edits**
1. Insert the full bidirectional event mapping table into §4.1; pin terminators (Chat client always `data: [DONE]`, Anthropic client always `message_stop`); make TF-6.8 assert terminator + `finish_reason`/`stop_reason`, drop the hedge.
2. Add a mid-stream error contract: 200 sent, protocol-shaped error frame, explicit `track` status; stop classifying via "status ≥ 400."
3. Add request-leg translate + pre-flight unsupported → 400 to the error table, with a negative E2E step.
4. Unify the local eunit command (CI-matching no-mount build, or mount+volume — one), and `rm -rf _build` in the stage.
5. Single-funnel counters: total at routing attempt; failed defined as an enumerated path set (provider error, crash, 4xx/5xx, mid-stream drain), with pre-routing 401/400 excluded by design.
