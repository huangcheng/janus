**1. Verdict:** GO WITH FIXES — the three-slice decomposition and sequencing are sound, but the SSE contract, counter semantics, and the image command as written are under-specified enough to cause a rework PR.

**2. Critical risks**
- *SSE contracts:* `message_start`/`content_block_start`/`message_stop` wrappers must be synthesized for Chat→Messages, but nothing says from which chunk fields (id? model? usage in `message_start` is mandatory). Thinking blocks out to an Anthropic client likely need `signature` — Claude Code rejects unsigned blocks. `finish_reason ↔ stop_reason` mapping (stop/end_turn, length/max_tokens, tool_calls/tool_use) is unspecified.
- *Mid-stream errors:* "send one client error frame if none sent; else close" — error frame shape per face undefined, and whether a terminal `[DONE]`/`message_stop` follows is unstated (clients hang otherwise). Teardown order (stop drain → track(400) → close) must not race `capture_usage_chunk`.
- *Disconnect/idle:* translating stream can't reuse `collect_drain`; sending to a half-closed socket must return `{stop,...}` not crash. 300s idle_timeout covers first-byte gaps but not long thinking gaps with zero deltas — define a keepalive or accept timeout.
- *Counters:* "proxied LLM calls only" vs SPEC §2.4 "requests" risks a dashboard error-rate mismatch (does janus-auto count 1 or N underlying calls? do LB failover retries count once?). Crash paths bypass `track/3` — who bumps `requests_failed` there? Bump must live in one place or double-count.
- *Docker/_build ABI:* §4.3's own command mounts `F:/Janus:/app` **without** the named `_build` volume the prose mandates — host `_build` shadows the image (the exact bug being fixed). CRLF autocrlf can break `rebar3` escripts on Windows mounts.
- *Deploy wait:* generation equality ≠ applied config (gateways poll + persistent_term distribution); wait must poll `:8090/stats` **with** `JANUS_STATS_TOKEN`, with an explicit timeout.

**3. Contradictions / stale claims**
- `translate_sse_chunk/3` (diagram) vs `translate_sse/2` (§4.1) — name/arity mismatch.
- §4.3 command contradicts its own named-volume requirement.
- Slice D "install/document gitleaks" is weaker than "hook skipped when binary missing" implies — no enforcement.
- Success criterion 4 ("no raw apk add") is not falsifiable; "no network to dl-cdn" is.

**4. Missing requirements**
- Full event mapping table (chunk fields ↔ events, usage, cache tokens, `reasoning_content` ↔ `thinking_delta`).
- Error-frame JSON per face + terminal-event rules.
- Per-connection state record fields (leftover iolist, block index, role-opened flag) and ownership.
- Counter unit definition, retry/fan-out policy, crash-path bump site.
- TF-6.8 upstream fixture: real Anthropic endpoint or mock SSE server? Streaming upstream shape for tools.
- Image: exact OTP/rebar3 pins, `_build` volume semantics across checkouts.

**5. Architecture notes**
Handler-process state is right (mirrors `janus_usage_head`/tail), but the drain callback for translate must return `{continue, State}`-style leftovers rather than accumulate. Keep usage parsing on **provider** bytes (correct). Atom­ics in persistent_term matches the `janus_usage` pattern; guard `/stats` with `catch` + `0`. Keep `pick_route` non-speculative in Slice B. TEST-FLOWS lives in the sibling repo — dual-repo PR pairing must be stated.

**6. Top 5 edits**
1. Add the bidirectional SSE mapping table (finish/stop reasons, usage, thinking `signature`, `message_start` synthesis).
2. Specify mid-stream error frame per face + terminal event + teardown order.
3. Fix `translate_sse_chunk/3` naming; enumerate handler state fields.
4. Define counter unit (client call, not upstream attempt), janus-auto policy, crash-path bump site — align wording with SPEC §2.4.
5. Rewrite the §4.3 command with the named `_build` volume + pinned OTP/rebar3; define the TF-6.8 upstream fixture.
