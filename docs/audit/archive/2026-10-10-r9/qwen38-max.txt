## Findings (fixes)

**F1 — E.6(c) contradicts the rev-9 `SampledAtMono` semantics (stale rev-7 clause).**
A.3/Part 0.9 pin: compare-before-overwrite is vacuous, true rule = last-arrival-wins bounded by TTL, existence gate + handler serialization are the protections. But Part E item 6(c) still says: *"never clobbers a newer `SampledAtMono` (write-time latest-wins)"* — implying a compare guard the spec elsewhere declares a no-op. An implementer writing that eunit would re-introduce the dropped mechanism.
Fix: rewrite 6(c) to assert the existence gate (probe result arriving after any unexpired row landed is discarded, wasting a paid probe) and that passive writes are last-arrival-wins with NO compare guard.

**F2 — Purge does not clear the probe in-flight map.**
Part 0.2 clear-list for `{Node => JobRef}`: done/error/nodedown/send-fail/ack-miss; Part 0.5 adds owner restart. The 10-min purge (Part 0.11) removes the tracked entry and skips the decrement for `Internal` — but never clears the in-flight map. A silently-lost probe (worker up, done never lands) leaves that node excluded from probe targets under `cadence` **permanently** until nodedown or pool restart — defeating the purge's purpose as the backstop for lost jobs.
Fix: one line — purge (and any reconcile removal) of an `Internal` entry also clears the in-flight map by JobRef.

**F3 — Unpinned live-drain exhaustion has no reason label.**
Part C: exhaustion reason = first non-ok outcome; *"drain-skips of unpinned candidates label the exhaustion too."* But the enum — metric `sched_dispatch_local_total{reason=empty_pool|capacity|drained_pin|send_fail|ack_miss}` and the five JSON keys — has no value for an unpinned drain-skip (`drained_pin` is named for the pinned case in Part 0.6). The TOCTOU window is bounded and rare, but the label must exist when it fires.
Fix: add `drained` to both the metric and JSON enums, or pin unpinned drain-skips to `drained_pin` explicitly.

## Pins (recommended, not blocking)

**P1 — 13.3b boot path with TEST_HOSTS and no mmdb.** "locus loads ASYNC at boot — only when geo was explicitly requested" reads unconditional on `JANUS_SCHED_GEO=1`; with no file (mmdb not in git/image, CI offline), a literal implementation attempts load → fails → auto-off → 13.3b's `geo_match_total{auto}` assertions die. Pin: *path unset/absent + non-empty TEST_HOSTS ⇒ boot OK, locus load SKIPPED entirely, geo serves injected hosts only, all other hosts unknown, no `geo_disabled_total`.*

**P2 — two wording seams.** (a) Part 0.6 still says exhaustion ⇒ `reason=capacity` as shorthand; point it at Part C's first-non-ok rule to avoid a hardcoded label. (b) Part 0.11's reconcile *"treats counter-excess older than one flush interval as drift"* — the counter is a scalar with no timestamps; pin the executable rule (e.g., skip correction while any tracked entry's `ReservedAtMono` is within one flush interval). Harmless either way (corrective writes heal negatives; bounded softness is already in the accepted class), but it's currently not mechanical.
