**1. Verdict:** GO WITH FIXES — plugin architecture is sound, but the video transport invariant and two contract/status contradictions must be resolved before M3 ships.

**2. Critical risks**
- **Video gun-budget vs listener idle invariant is violated for ASYNC submit.** A5 states `budget < caller's SSE window` with video default 600s, but async POST replies JSON and CLOSES under `idle_timeout=300s` — no SSE window exists, so the handler is killed at 300s before gun's 600s budget. Either cap async-submit budget <300s or make submit SSE.
- **Poll SSE has no max-hold.** A never-terminal job streams indefinitely; needs an `exp`-bounded hold + guaranteed terminal.
- **Default-allow entitlement mutates the blocked predicate.** Must prove no existing key regresses (eunit + E2E) and confirm the carrier is allow-list, not deny-list.
- **Rolling deploy:** only *dashboard* tolerance for an un-migrated gateway is stated. New gateway code on a follower before the leader's migration will fail writes on `modality`/`units`/`status`/`jvid`. Needs a migration gate or dual-read.
- **ASR reply cap "stop streaming, status=truncated" corrupts buffered JSON** — same corruption class as a truncated b64 image; should pass through + warn.

**3. Contradictions / stale claims**
- Contracts says cancel is `409 on sync-mode ids`; A5 says "No sync-409 branch exists." Delete the Contracts 409.
- `commit_point/1` returns `pre_2xx`, but A6 prose says images commit AT 2xx headers. Rename/clarify.
- A4 lists only `modality`+`units`; M1.1 also adds `status`+`jvid`.
- Prompt framing cites "per-route timeout overrides"; the plan correctly rejects it — ensure no task reintroduces it.
