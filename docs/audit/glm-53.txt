# Audit — Janus Phase 1 spec (round 9)

## 1. Verdict

**GO** — no two sentences contradict each other outside §10's settled decisions; remaining gaps are specification detail, not design flaws.

## 2. Critical risks

- **Usage-row wiring on translating 200s**: disconnect/502 paths specify `capture_usage_chunk`, but the success path never says who calls it with `#sse_st{}` token counts after `finalize_sse(normal)`; TF-6.8's "tokens not both null" depends on this unstated call site.
- **Error-frame format lives only in the §4.1.4 table**: `finalize_sse`'s contract lists `{error, invalid_request|upstream, Msg}` but not the sanitized frame shape (≤200 bytes, no URL/auth) — easy to implement divergently per face.
- **Docker/_build ABI**: volume `janus-ebin-otp27` is keyed to major OTP only; an image rebuild that bumps the OTP patch could pair stale beams with a new runtime before the documented "recreate on OTP change" rule triggers.
- **Protocol compat**: Anthropic face correctness (first `message_start`, `event:` lines, no `[DONE]`) is only asserted in Slice B's E2E text; nothing pins it in TF-6.8b assertions themselves.
- **Deploy wait**: gen0 source ("dashboard DB") names no table/query; step 1's "after catalog apply" needs a concrete verification signal.

## 3. Contradictions or stale claims

None material. Minor underspecification: synthesized OpenAI usage chunk says `id`/`object`/`model` "from St" but St has no `object` field and `model` may be `undefined` (provider omitted it).

## 4. Missing requirements

- Success-path usage capture (see §2) — exact call site and argument shape.
- `object=chat.completion.chunk` and a `model` fallback (e.g. `<<"unknown">>`) for the usage chunk.
- `sse_events` behavior when an Anthropic frame lacks `event:` (type undefined — ignore+log?).
- §7 Phase 1 B file map omits `../janus-dashboard/docs/TEST-FLOWS.md` although §4.2 requires TF-6.1 reclassification plus 404/401/janus-auto counter assertions.
- Slice D: gen0 query, and whether `uptime_sec` check excludes nodes whose digest didn't change but rebooted for other reasons.

## 5. Architecture / design notes

Handler-owned `#sse_st{}` with pure `translate_sse` is right; per-fold writes avoid frame buffering. Keep `inc_total`'s inner-no-op inside `janus_http_stats` (not at call sites) so bump sites stay single-funnel. Atomics-in-`persistent_term` before listeners is correct for boot ordering; note eunit boots `janus_usage` in a different app — counter tests must not assume `janus_http_app` ran. FastAPI passthrough must label counters per-node-since-boot, matching SPEC §2.4's counted population.

## 6. Top 5 concrete edits

1. §4.1.2: add "on translating-200 terminal, handler calls `capture_usage_chunk` with `in_tokens`/`out_tokens` from St" — success, not just 502.
2. Move the sanitized error-frame format into `finalize_sse`'s contract; §4.1.4 keeps only status/counters.
3. §7 Phase 1 B: add `../janus-dashboard/docs/TEST-FLOWS.md` (TF-6.1 + counter assertions).
4. Slice C: bake OTP build into the volume name or make `docker volume rm` part of the documented rebuild step; specify `event:`-less Anthropic frame handling.
5. Slice D step 0: name the gen0 source table/column and the post-apply leader verification probe.
